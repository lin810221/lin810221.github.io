## 不同輸入可以放在一起比較嗎

文字與圖片原始格式不同，卻可能描述同一內容。跨模態表示透過相應訓練，讓文字 encoder 與圖像 encoder 的輸出落在可比較空間。它們不必共享同一個 backbone，但必須有共同對齊目標。

把獨立文字模型與獨立圖片分類模型的向量都轉 512 維，不能因此直接比較。維度相同只是運算能進行，不代表已學到跨模態關係。

## CLIP 的核心方向

CLIP 以大量圖文配對學習對比關係，在一個 batch 中提高對應圖文的匹配程度。圖像與文字各自編碼，再比較相似度；這支持文字找圖、圖找文字等應用。[CLIP 原論文](https://arxiv.org/abs/2103.00020)

相似度矩陣可以有圖→文與文→圖兩個方向的目標。batch 中其他內容作負配對，也會遇到其實描述相近的 false negatives。訓練資料與 captions 的品質決定哪些關係容易學到。

## 推論時的資料流

```text
圖片庫 → 對應圖像 encoder → 保存向量與圖像 ID
文字查詢 → 配對文字 encoder → 比較 → 回傳圖像
```

影像縮放、裁切、色彩與正規化等 processor 設定屬於模型契約。不能用不同預處理產生文件圖像向量，再期待文字側自動修正。

## Zero-shot 類別描述

可以編碼多個文字類別描述，與圖片比較做候選排序。描述的語言、模板與候選集合都影響分數；softmax 仍是這些候選中的相對分配，不是所有可能類別的真實機率。

若圖片包含細小數字、複雜表格或文字，圖文模型不一定具備精確 OCR 與計算能力。可另接 OCR、結構化抽取與規則，而不是把所有細節都交給相似度。

## 評估與資料限制

測文字找圖的 Recall@k、圖片找文字的對應指標，以及不同語言、版面與細節題。不要只用很容易辨認的動物照片展示，再推論能找技術圖紙的精確規格。

使用資料時保存來源、授權、隱私與版本。跨模態向量也可能保留敏感特徵，存取政策不能因它變成數字就消失。

## 圖文配對矩陣怎麼讀

一個 batch 有三張圖與三段對應描述，可形成 3×3 相似度矩陣，對角線是指定正配對，其他位置是候選負配對。但若兩張圖其實都是同一隻貓，不同對角線之外也可能是合理描述。

這再次說明對比學習依賴資料標籤；圖片與文字的數量和順序要正確映射。模型沒有因跨模態而免除 false negatives、來源授權或評估切分問題。

## 練習與參考答案

**題目：**把文字向量與另一個獨立圖片模型輸出接到同一向量庫，是否就完成 CLIP？

**參考答案：**沒有。需要相容的對齊訓練與 processor 契約。資料庫只是儲存與搜尋工具，不能替不同座標系建立語意對齊。
