# CSV的型別、引號與前導零

簡單文字格式也需要明確schema與成熟的解析器。

## 逗號不是唯一的分隔規則

CSV欄位可能含逗號、換行與引號，解析需要遵循引號及跳脫規則。用字串split分逗號，會把合法欄位拆錯。來源還可能使用不同編碼、換行、分隔字元或空值表示，都應記入契約。

## 不讓自動推論決定業務鍵

範例外部識別是001、002、003，必須保存前導零。若推論成整數，再轉成字串也無法知道原來有幾個零。金額則明確讀成DECIMAL，文字備註可以合法含有逗號與雙引號。

```python
rows = connection.execute("""
 SELECT * FROM read_csv(?,header=true,columns={
 'external_id':'VARCHAR','amount':'DECIMAL(12,2)','comment':'VARCHAR'})
""", [str(path)]).fetchall()
```

## 錯誤不能靜默消失

若採用忽略錯誤或寬鬆解析，還要保存被拒絕列、原因與來源位置，並對帳輸入與輸出。解析器成功讀到部分資料，不表示已讀完整檔案。欄位次序變更、新增欄位與多出的分隔字元也要有策略。

## 實驗目標

確認001仍為字串、第一筆備註是quoted comma文字、最後一筆保留內部引號。這些很小的反例能攔住常見錯誤。後續再量測大型CSV推論與讀取成本，但不以這三筆資料的耗時作正式結論。
