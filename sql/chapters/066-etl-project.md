# 完成第一條ETL與ELT流程

讓每一層有可保存、可檢查與可重建的成果。

## ETL與ELT差在哪裡

ETL通常先轉換再載入目標分析系統，ELT則先載入再由目標系統轉換。兩者都需要契約、品質與重跑設計，不應把字母順序當成成熟度排名。某些流程也會混合使用。

## 本課的最小成果

從合成CSV或JSON讀取資料，保存原始識別，轉型金額與時間，分類失敗原因，去重後計算指標。每一步都留下筆數與鍵檢查，再把通過結果寫成可回讀的檔案或資料表。

先只做一個小範圍，核對來源五筆訂單與付款13000美分。加入退款後再核對淨額11000。若此時數字不對，先修正粒度與轉型，不要急著增加排程或換分散式平台。

## 交付內容

保存來源fixture、轉換SQL、Python入口、環境版本與預期結果。對輸入錯誤、重送與程序失敗各準備一個案例，說明重跑會讀哪個範圍、哪些副作用可能已發生，以及如何驗證恢復。

後續的增量、排程和倉儲，只是在這條可重現主線上增加時間與協調責任。無論未來採Airflow、dbt或其他工具，都應繼續保留這份可手算、可自動驗收的最小流程。
