# 從檔案讀寫到可驗證交付

讀得進來和交付得可靠，是兩個需要分別驗收的成果。

## 讀取端檢查

CSV先看型別、引號、編碼和空值；JSON先看外框與契約；Parquet再看schema、列組與必要欄位。格式不一樣，但都需要知道每列代表什麼、單位是什麼，以及哪一批來源形成這份資料。

## 寫入端檢查

輸出成功後重新開啟讀回，驗證筆數、鍵、總額與必要型別。檔案寫入函數沒有拋例外，只證明它完成某個操作，不代表下游可以正確理解或目前公開指標已指到這個版本。

## 保留來源與產出關係

記錄來源檔案雜湊、轉換版本與輸出manifest，讓相同輸入可以重建。若來源檔案會被覆寫，只有檔名沒有版本並不足夠。雜湊也不等於資料品質；內容可以完整保存，但本來就是錯的資料。

## 發布前的最小演練

故意損壞一個已發布Parquet，回讀應因雜湊或解析失敗而拒絕；再讓一個批次在寫檔前中斷，讀取者應仍看到上一個完成版本。這些反例會在專題測試中實際執行，不只描述理想流程。

最後再決定是否需要物件儲存、資料湖表格式或外部catalog。它們可以提供更多協調能力，但不會自動替你的業務指標定義正確分母。
