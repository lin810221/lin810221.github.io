# DAG、依賴與拓樸排序

排程之前，先把哪些工作必須先完成畫清楚。

## 工作和資料集是不同節點

一個工作可能讀取多份資料、產生多份產物。工作依賴表示執行的先後條件，資料血緣則描述產物從哪裡來；兩張圖相關但不相同。不能只因DAG執行成功，就推定每份輸出都符合資料契約。

## 無循環的先後關係

拓樸排序會產生符合依賴的工作順序。若有未知父工作或循環，就在開始執行前拒絕。本課演算法以固定規則挑選同時可執行的節點，讓教學結果可重現；這不表示正式系統必須採用相同排序。

## 從圖走到真實執行

下載包的orchestrator會呼叫實際Python工作，限制可重試錯誤與嘗試次數；workflow將第一批、第二批和快照驗證接成DAG。它是手動、單程序執行器，不是長期運行的排程服務，也不冒充Airflow。

```powershell
python workflow.py --workspace .runtime/workflow-demo
```

這個指令可以重新執行；資料處理的冪等由DataHarbor批次契約保護，而不是因為DAG圖有箭頭就自動成立。

設計DAG時，先讓工作邊界對應可驗收的成果，再考慮並行。將每條SQL任意拆成一個節點，可能只增加協調成本；反過來把所有事情包成一個節點，又可能無法定位與重跑特定階段。

## 專案中的實作

節錄 `examples/contracts.py` 的 `topological_sort`。請以完整下載包執行，共用匯入與資料契約不可省略。

```python
def topological_sort(dependencies):
    nodes=set(dependencies)
    if any(parent not in nodes for parents in dependencies.values() for parent in parents):raise ValueError('Unknown dependency')
    incoming={node:len(set(parents)) for node,parents in dependencies.items()}
    children={node:[] for node in nodes}
    for node,parents in dependencies.items():
        for parent in set(parents):children[parent].append(node)
    ready=[node for node,count in incoming.items() if not count];heapq.heapify(ready);result=[]
    while ready:
        node=heapq.heappop(ready);result.append(node)
        for child in sorted(children[node]):
            incoming[child]-=1
            if not incoming[child]:heapq.heappush(ready,child)
    if len(result)!=len(nodes):raise ValueError('Dependency cycle')
    return result
```
