# ER關係、基數與多對多橋接

用關聯方向與唯一性約束，說明哪些配對是允許的。

## 一對多與可選關聯

客戶可有零到多筆訂單，每筆訂單則必須有一位客戶。可選性與基數是不同資訊：某側可為空，不表示同一鍵可以任意重複。圖上的線要和資料庫的NOT NULL、UNIQUE與外鍵相呼應。

## 多對多需要明確的橋接粒度

一筆訂單可包含多種商品，同一商品也可出現在多筆訂單，因此通常由訂單明細連接。若同一商品在同一訂單可分成不同批次或價格列，橋接鍵又不一定只是訂單與商品的二欄組合；應依真實業務事件決定。

錯誤地加入唯一約束，可能把合法資料拒絕；沒有必要的唯一約束，則可能讓相同配對被重複保存。兩者都需要具體反例驗收。

## 檢查刪除行為

刪客戶時，是拒絕、有條件清理，還是保留歷史後去識別？刪訂單時明細是否同步處理？外鍵的刪除選項不是單純方便的設定，會影響資料保存與追溯。不同引擎對各選項支援也要分別確認。

閱讀本課圖解時，先找實體鍵，再在每條邊旁註記「最多幾筆」與「可否沒有」。這能在寫SQL之前提早發現fanout和歷史資料需求，避免等報表翻倍才回頭猜模型。
