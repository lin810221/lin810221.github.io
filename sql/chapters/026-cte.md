# 以CTE拆開資料轉換

用命名中間結果建立可讀的查詢，不把語法外觀當成效能保證。

## WITH的作用

CTE是同一敘述內的命名查詢，能依賴前面的CTE，也能讓複雜SQL分成數個可檢查步驟。名稱最好說明資料的粒度或責任，例如item_totals與refund_totals，而不是只取a、b、c。

本課fanout修正就是先分別計算每訂單的商品與退款總額，再將兩個命名結果接回訂單。讀者可以暫時只SELECT某個CTE，先看鍵是否唯一與總額是否正確，再繼續完成報表。

## 不要把CTE當成強制暫存表

DuckDB和PostgreSQL會按產品、版本與查詢情況決定物化或內嵌。DuckDB 2.0的預設與最佳化條件有明確文件，也有物化提示；這些提示不是可攜SQL的通用承諾。若效能或重複計算真的重要，就查看實際計畫與量測，不憑WITH關鍵字判定。

## 除錯方法

每個CTE寫下輸入、輸出鍵、會不會過濾列與可能的空值。把長查詢分解後，常能發現某個聚合太早、某個條件太晚，或某個中間層根本沒有維持預期唯一性。

如果中間結果需要跨多個工作保存、被其他使用者查詢或獨立重建，就要考慮View、表或管線模型；CTE只在當前敘述的範圍內存在，不是排程或持久化機制。

## 可執行查詢

以下是下載包 `queries/08.sql` 的實際內容；先由 `fixtures.seed` 建立本課合成資料。執行入口會建立獨立資料庫，不需修改既有資料。

```sql
WITH item_totals AS (
  SELECT order_id, SUM(quantity * unit_cents) AS gross_cents FROM items GROUP BY order_id
), refund_totals AS (
  SELECT order_id, SUM(amount_cents) AS refund_cents FROM refunds GROUP BY order_id
)
SELECT o.order_id, i.gross_cents, COALESCE(r.refund_cents,0) AS refund_cents,
       i.gross_cents - COALESCE(r.refund_cents,0) AS net_cents
FROM orders o JOIN item_totals i ON i.order_id=o.order_id
LEFT JOIN refund_totals r ON r.order_id=o.order_id
WHERE o.status='paid' ORDER BY o.order_id;
```
