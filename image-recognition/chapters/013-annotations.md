先定義答案的含義與合法結構，再設計標註、稽核與模型介面，避免把不同任務的 ID 規則混用。

## 標註是可學習目標的來源

模型學的是資料中提供的答案。標註者對裂縫、陰影、可見邊界與遮擋的判斷若不一致，訓練會收到互相矛盾的訊號。資料契約不只是檔案格式，還包含類別定義、排除條件、邊界政策與難判案例。先建立幾張有代表性的正例、反例及模糊例，讓不同人知道同一問題應如何作答。

例如「瑕疵」是任何可見痕跡，還是長度超過門檻的結構缺陷？嚴重反光看不清時，標為正常、未知或忽略？完全遮住的物體是否標註？這些選擇取決於任務，不應由標註工具預設值決定。先明定規則再檢查一致性，比在模型訓練後猜測資料含義有效。

## 三種任務的 ID 不同

| 任務 | 本課示範映射 | 背景／忽略規則 |
| --- | --- | --- |
| 分類 | 0=圓形，1=矩形 | 0 是合法第一類；未知另定政策 |
| 偵測 | 1=圓形，2=矩形 | 0 保留背景；沒有物體用空目標 |
| 語意分割 | 0=背景，1=圓形，2=矩形 | 255=忽略，不加入一般類別 |

這是為不同 loss 與模型 API 建立的明確契約，不代表同一物體在所有任務必須使用相同數字。保存 `class_to_idx` 與反向映射，並隨模型產物一起版本管理。若依資料夾排序臨時產生 ID，部署端又用另一份排序，模型即使輸出完全相同也會被解讀為錯誤類別。

## 偵測資料應包含什麼

本課框採連續半開 XYXY，畫布為處理方向後的 H、W。`boxes` 為 N×4 float32，`labels` 為 N 個 int64 前景 ID；每個逐實例欄位的第一維都對應同一個 N。空圖應為 shape `(0,4)` 的 boxes 與 shape `(0,)` 的 labels，不用一個零框代表空圖。

以下是資料設計示意，`objects` 只示範標註結構，不依賴特定課程程式檔。影像尺寸與框座標必須由真正檔案交叉檢查。

```json
{
  "sample_id": "sample-001",
  "group_id": "capture-session-01",
  "file": "images/sample-001.png",
  "width": 96,
  "height": 64,
  "objects": [{"label": 1, "box_xyxy": [12, 8, 40, 36]}]
}
```

框面積是 $28\times28=784$。若標註工具輸出的是左上角加寬高 `[12,8,28,28]`，必須先轉換格式，不能只改欄位名稱。COCO、YOLO 等格式在座標單位、類別索引及欄位含義上不同，匯入前寫清楚轉換，匯出後再畫回原圖驗證。

## 語意與實例 mask 的差別

語意 mask 為 H×W，每像素存類別 ID；彩色預覽圖可以幫人閱讀，但不要把調色盤顏色直接當原始類別值。實例分割則需要每個物體自己的 mask，例如 N×H×W。即使兩個圓形接觸，仍可保存兩個實例，這與把所有圓形塗成同一類別不同。

ignore 像素必須在 loss、指標及視覺化圖例中一致處理。若把 255 當前景，IoU 分母與模型目標會出錯；若只忽略困難區域卻不報告忽略比例，結果也可能過度樂觀。標註遮擋／未知的政策需要隨資料版本保存，不可事後為了提高成績任意修改。

## 標註品質如何驗收

先驗證結構：檔案存在、可解碼、尺寸一致、ID 合法、框正面積、沒有非有限值、逐實例欄位長度一致。再抽查語意：框是否框住正確物體，mask 是否對齊，類別邊界是否一致。最後分析標註者分歧，分歧可能暴露任務本身模糊，不只是某位標註者不認真。

資料版本應包含原圖來源與授權、標註規則、映射、修改紀錄及切分清單。刪除錯誤標註後重新評估時，說明變動，不能只留下較好看的新數字。任何模型預標註都應保留人工覆核與錯誤抽樣，避免模型自己的偏差成為看似客觀的真值。

## 練習與解析

**題目：** 一張有三個框的影像，裁切後只剩兩個框，labels 卻仍有三個；模型報 shape 錯誤時能否只截短 labels？

**解析：** 不能盲目截短，必須以同一個保留索引同步過濾框、labels、masks 等欄位，否則剩下的類別可能與物體錯配。資料驗證要檢查對應關係，而非只讓 shape 通過。空目標也應有明確結構與可測試範例。
