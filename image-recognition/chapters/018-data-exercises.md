## 以可檢查產物作答

資料工程練習的答案不只是一行模型程式。請準備類別映射、split manifest、稽核清單、增強疊圖與批次 shape 記錄。每一項都能對應到資料版本與樣本身分，才有辦法在模型結果變動時查出原因。以下案例是人工設定的教學情境，與真實資料集效能無關。

作答時先問「希望泛化到什麼」，再問「哪些資料能參與這個選擇」。後者涵蓋切分、均值、門檻、類別權重、標註修訂與增強調整。把 test 欄位保留在 CSV 裡並不代表已防止洩漏；實際程式讀了哪些列才是關鍵。

## 題目一：定義新物件測試

100 個實體零件，每個拍攝 10 張，共 1000 張。需求是在新零件上辨識外型。先對每張圖旋轉產生 5 份，再隨機切成 train／val／test，有什麼問題？修正後是否一定每類都有測試樣本？

**解析：** 原圖、衍生圖與同一實體零件的近似照片可能跨集合。應以原始零件 ID 群組切分，再只在 train 端增強。是否每類都有獨立群組取決於原資料；某類若只有一個零件，不能拆開它來假裝同時有獨立訓練與測試。要補資料或明列該類泛化無法估計，而不是只追求表面比例。

## 題目二：ID 與空目標

分類 circle=0、rectangle=1 的映射可以原封不動送進本課偵測 API 嗎？一張沒有物體的影像是否應標一個 `[0,0,0,0]` 框、label=0？語意 mask 的 0 又是否一定要忽略？

**解析：** 本課偵測前景從 1 起，0 保留背景，需有明確任務映射。空圖使用 `(0,4)` boxes 與 `(0,)` labels，不是假造零面積背景框。語意分割的 0 是合法背景類，255 才是本課 ignore；分類與分割不能照抄偵測的背景保留規則。映射和 ignore 政策都要保存及驗證。

## 題目三：統計量與偷看答案

你先讀完全部影像計算 RGB 均值、標準差，再建立切分，認為沒有使用 label 就不算洩漏。問題在哪？若改用預訓練權重提供的 transforms，是否也等同從 test 計算？

**解析：** 全部影像包含測試分布，資料驅動的前處理已利用測試資訊。通常應先切分，只從 train 估計統計量。使用事先固定的外部權重前處理是不同情況，沒有由本次 test 重新估計，但需記錄來源並檢查是否適合任務；仍不能用 test 成績反覆選擇各種前處理。例外如明定的 transductive 協定需另外說明，不能默默混入一般未見評估。

## 題目四：共同增強

寬 100 的圖，框 `(10,5,30,25)`，影像做水平翻轉但 mask 沒翻。請寫新框並說明如何設計一個能抓出錯位的測試。只檢查框仍在畫布內是否足夠？

**解析：** 新框是 `(70,5,90,25)`。建立已知前景矩形的合成圖，把 image、框與 mask 共同傳入確定翻轉，再比對框邊界、mask 前景範圍與影像前景。只檢查框合法不足，錯位框也可能完全在畫布內。隨機增強測試可先固定參數驗幾何，再檢查隨機流程，避免測試自己也不穩定。

## 題目五：資料載入與樣本總數

測試集有 23 張，batch size=8，drop_last=True。某張壞檔在 Dataset 裡被替換成上一張，程式仍跑完。這兩項選擇如何改變評估？Windows 將 num_workers 從 0 改 4 又可能遇到什麼？

**解析：** drop_last 只評估 16 張，另外 7 張未計入；替換壞檔使樣本身分與答案不再對應，且重複了別張的權重。應先稽核並依政策處理壞檔，評估涵蓋所有合法樣本。Windows 多進程需 main guard、頂層可序列化函式，還可能出現記憶體與啟動成本；不是 workers 越多就必定越快。

## 題目六：雜湊與近重複

兩張圖看起來相同，但 JPEG 品質不同，檔案 SHA-256 不同。是否已證明它們是獨立樣本？如果感知相似度很高，是否可以自動刪除其中一張？

**解析：** 檔案 hash 不同只表示 bytes 不同，不能排除重新編碼或裁切副本。可追加像素與感知層級檢查、來源追蹤及人工覆核。高相似度也不必然是重複，標準零件本來可能很像；先判斷群組與資料來源，再決定隔離或刪除政策，保留可追溯紀錄。

## 整合挑戰與完成標準

用自行產生的圖建立至少三個群組，包含一張空目標、一張貼邊目標、一個含 ignore 的 mask 與一個故意壞掉的檔案。產出合法清單、切分表及疊圖，檢查群組不相交、非法 ID 被攔截、壞檔被記錄、增強後目標同步、最後一批不被丟掉。

完成後說明這個小測試的限制：少量合成群組只能驗證管線規則，不足以估計真實部署準確率。接下來才使用固定協定訓練模型，並在不改動資料邊界的前提下比較方法。
