從九個數字的加權和開始，理解平滑、銳化、相關與卷積，以及為什麼邊界條件會改變答案。

## 一個視窗如何產生一個值

濾波器把小型權重表，也就是 kernel，在影像上移動。每個位置取出附近像素，乘上對應權重再加總，得到輸出。它用的是局部資訊：3×3 視窗一次看到九個位置，不能直接理解整張照片的物體意義。平滑可壓低某些快速變化，銳化或微分則強調變化，結果取決於 kernel 與資料條件。

對單通道輸入及中心錨點，一種不翻轉 kernel 的互相關記法為：

$$
Y[y,x]=\sum_{i=-1}^{1}\sum_{j=-1}^{1}K[i+1,j+1]X[y+i,x+j]
$$

數學上的卷積還要翻轉 kernel；常見深度學習 Conv2d 實際採互相關形式。對稱平均核翻轉前後相同，不容易看出差別；非對稱邊緣核會改變方向或符號。因此讀到「卷積」時，要核對該函式真正計算的定義。

## 手算平均與噪音

原視窗為 `[[0,0,0],[0,90,0],[0,0,0]]`，3×3 平均核每個值為 1/9，中心輸出是 10。原本集中的亮點被分散到附近，局部極端值減小；一個真實的小目標也可能同樣被抹淡。平滑不會知道哪個高頻訊號是噪音、哪個是你要辨識的細節。

Gaussian 讓較近位置權重較高；median 用鄰域中位數，是非線性運算，不能簡單寫成固定權重和。椒鹽噪音可能適合中位數，但細線也可能被移除。選擇方法前先建立一張含平坦區、斜邊、細線與脈衝點的合成圖，用同一尺度比較資訊保留與噪音抑制。

## 邊界不是自動有答案

3×3 視窗在左上角會需要影像外的值。補零、複製邊緣、鏡射、只算有效區域，都是額外假設。對一張所有值皆為 100 的圖，平均核加補零時，左上角只看見四個有效像素，輸出約 $\frac{400}{9}\approx44.44$；採能維持常數的邊界延伸則仍是 100。黑邊可能來自補值規則，不是原圖真的有一條暗線。

實作中 kernel 大小、anchor、stride、padding 和輸出 dtype 都要一起記錄。讀圖是 uint8，不代表所有中間運算都該用 uint8；負值與超過 255 的響應可能是有意義的訊號。若過早轉回 8-bit，截斷與飽和會掩蓋差異。

## 一段可檢查的運算示意

```python
import numpy as np
import cv2

x = np.full((5,5), 100, dtype=np.float32)
k = np.ones((3,3), dtype=np.float32)/9
zero = cv2.filter2D(x, -1, k, borderType=cv2.BORDER_CONSTANT)
rep = cv2.filter2D(x, -1, k, borderType=cv2.BORDER_REPLICATE)
assert np.isclose(zero[0,0], 400/9)
assert np.isclose(rep[0,0], 100)
```

這個例子固定 float32 且選定兩種邊界，讓誤差來源容易隔離。OpenCV `filter2D` 的 kernel 不自動翻轉，做嚴格數學卷積時需自行處理。若換成不對稱 kernel，先手算某一個內部位置，再與函式結果比對，避免單憑圖像外觀猜公式。

## 從固定濾波連到 CNN

傳統濾波由人指定 kernel；CNN 的權重由任務 loss 學出。多輸入通道時，卷積會對各通道的局部響應相加，再形成多個輸出 feature map。網路不必每層都「先找邊緣」才工作；那是部分模型可觀察的模式，不是強制演算法。這裡先學會運算，後續架構單元再討論權重如何學到。

## 練習與解析

**題目：** 3×3 平均核的權重總和若是 9 而非 1，常數值 20 的內部輸出是多少？平滑後雜訊少了，就能保證分類更準嗎？

**解析：** 每項都乘 1，九項相加得到 180，這是放大而非平均；uint8 還可能飽和。平滑可能移除關鍵小目標，需以相同資料切分比較任務指標，並檢查不同目標尺寸的錯誤。看來乾淨不等於保留了有用訊號。
