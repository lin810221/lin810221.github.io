## 從影像到辨識任務

**題目：** 便利商店想知道架上每種飲料剩幾瓶，整張照片只分類為「有飲料」是否足夠？若瓶子互相遮住，換分割就一定能數對嗎？

**解析：** 需要個體位置或個體遮罩，才能對每類計數；整張分類沒有個體資訊。遮擋使可見證據不足，分割也不保證推回完全看不見的瓶子。可考慮調整相機、拍攝多視角或接受有界的計數不確定性。先建立可回答與不可回答的情境，再選模型及資料。

**解析：** mask 很可能被當影像除以 255，類別 1 被改成約 0.0039，應保留整數標籤與 ignore 規則。影像的負數可能只是低於均值的合法標準化值，兩者不能用同一範圍判準。

**解析：** 先檢查 alpha 合成政策，黑色可能來自丟棄透明度後暴露的隱藏值。灰階複製成三通道可滿足某些模型輸入形狀，卻不會生成缺失的色彩資訊，應記錄資料來源與模式。驗證時至少使用紅／藍色塊、透明像素、EXIF 旋轉圖與損壞檔等案例。

**解析：** 正確是 `(60,5,80,25)`。錯誤結果把像素索引翻轉規則套到半開邊界，讓貼右邊的目標向左偏移。另請手算裁切原點、縮放與 padding 的組合，並把正向和反向映射都寫進推論輸出契約。

## 影像入門練習與解析

# 影像入門練習與解析

用一組有明確答案的資料契約題，驗收影像形狀、讀圖政策與幾何操作是否真的一致。

## 作答方式與驗收目標

先在紙上寫出預期值，再用小段程式驗證。不要只回答某個 API 名稱；每題都要指出輸入的 shape、dtype、範圍與座標系。本組使用人工設定數值，不依賴下載影像或已有模型。做錯時回到前處理和資料契約查原因，這些錯誤通常不會靠多訓練幾個 epoch 自動消失。

建立一張檢核表，欄位為「假設、操作、預期、不應發生的結果」。例如假設輸入 RGB uint8，操作為轉 float32／255，預期最大 1，不應仍最大 255。這張表之後可延伸成資料集稽核與部署一致性測試，讓同一條規則不必靠記憶維持。

## 題目一：形狀與記憶體

一張 RGB 圖的 NumPy shape 為 `(48,80,3)`。將它轉為模型單張 CHW 與 batch size 5 的 NCHW，shape 各為何？輸入 batch 若是 float32，需要多少 bytes？可以直接用 `reshape` 取代換軸嗎？

**解析：** CHW 是 `(3,48,80)`，NCHW 是 `(5,3,48,80)`。輸入記憶體為  $5\times 3\times 48\times 80\times 4=230400$  bytes，約 225 KiB，尚未計入模型、活化或其他拷貝。使用 `permute(2,0,1)` 或相應的 transpose，不能以 reshape 取代：reshape 只重新排列索引解讀，無法表達想要的通道換位。驗證一個非灰色像素比只看 shape 更有力，因為錯誤程式也可能產生正確形狀。

## 題目二：同一數字有不同語意

影像像素 255、分類 label 0、語意 mask 值 255，各代表什麼？若對它們一起呼叫「轉 float 並除以 255」，會留下什麼後果？

**解析：** 影像 255 可能是某通道的最高 8-bit 編碼值；分類 0 可以是第一類；語意 mask 的 255 在本課是忽略標記。影像可依契約轉到 0–1，label 與 mask 應保留整數 ID。mask 裡類別 1 被除成 0.0039 後再轉整數會消失，原本的 255 又變成 1，造成答案被徹底改寫。忽略像素也需在評估時排除，不能只在 loss 裡忽略。

## 題目三：透明圖與方向

一張 RGBA 產品圖在瀏覽器是白底，但直接 `.convert('RGB')` 後背景變成深色。另有一張手機照片瀏覽器為直立、陣列尺寸卻橫向。分別應先查什麼？若框是人工在瀏覽器上標的，應如何驗證它仍對齊？

**解析：** 第一個先查 alpha，明定背景合成規則；單純丟掉 alpha 不等於畫面上已合成的顏色。第二個核對 EXIF orientation 與解碼器方向政策。選擇處理方向後，要確認標註採相同座標系；在圖上畫出框與已知位置，再抽查不同方向圖。必要時一次性轉存標準圖並重建或轉換框，保留原始資料與變換紀錄。不能只把 W、H 交換而未處理位置。

## 題目四：框的邊界

畫布  $W=120$ 、 $H=80$ ，框為 `(10,20,40,60)`。請算面積、水平翻轉後的框，以及等比例縮小一半後的框。右下邊界是否需要減 1？

**解析：** 面積  $30\times 40=1200$ ；水平翻轉後 `(80,20,110,60)`；原框縮小一半是 `(5,10,20,30)`，面積變為 300。半開連續邊界不減 1。整張畫布的框是 `(0,0,120,80)`，它完整描述影像覆蓋範圍，但 `image[80,120]` 仍是越界索引，因為邊界座標不是像素索引。

## 題目五：裁切後的空目標

裁切視窗為原圖 `50,100)×[10,60)`，原框為 `(10,20,40,45)`，標籤為 1。若只把座標扣除裁切原點，得到負 x 後直接截成 0，會出現什麼？應保留 `(0,10,0,35)` 嗎？

**解析：** 框完全在視窗外，截邊後寬為 0，不能當成有效偵測目標。移除框時必須同步移除對應 label、mask、area 等逐實例欄位。若全部移除，應回傳正確形狀的空目標，或依明定政策重新抽樣；不能留下無意義的零框來假裝有一個物體。空圖本身可能是有用訓練資料，要與「資料損壞」區分。

## 實作挑戰：用故意錯的輸入測試

自行產生紅藍色塊、灰階、透明背景、貼邊矩形與空影像。為每種輸入列出通道及位置預期值。再故意把 HWC 用 reshape 改成 CHW、把 BGR 當 RGB、把 mask 除以 255，觀察哪項檢核會先失敗。好的檢核要能抓出錯誤，而非只在正確輸入時成功。

完成標準是能解釋失敗來源並修正政策；若程式未執行，就記錄為手算／靜態練習。不要將這些入門合成題的通過數量當作真實辨識效能。

## RGB灰階與色彩空間

**題目：** 兩類產品外型相同，唯一差異是紅色／綠色標籤；將資料轉灰階是否一定有利？一張白色物體的 HSV 色相落在藍色範圍，又是否能直接判成藍色？

**解析：** 灰階可能移除關鍵顏色訊號，需先看轉換後仍可辨識否。白色物體飽和度低，色相數字不足以代表穩定顏色；規則至少要一起檢查 S、V，並用實際部署照明驗證。保留原始 RGB 圖，讓前處理選擇能重做與比較。

## 縮放插值與長寬比

**題目：** 一張  $200\times 100$  圖放入  $100\times 100$  畫布，等比例補邊後原點 `(40,20)` 到哪裡？mask 的邊界出現 `{0,0.5,1}` 是否合理？

**解析：** 比例 0.5，新圖  $100\times 50$ ，上下各補 25，座標變為 `(20,35)`。若它是硬類別 mask，0.5 是不合法的新標籤，應查是否誤用雙線性或把 mask 當連續影像。連續機率圖則可能合法，但它的訓練目標、loss 與閾值都需另外定義。

## 濾波卷積與邊界

**題目：**  $3\times 3$  平均核的權重總和若是 9 而非 1，常數值 20 的內部輸出是多少？平滑後雜訊少了，就能保證分類更準嗎？

**解析：** 每項都乘 1，九項相加得到 180，這是放大而非平均；uint8 還可能飽和。平滑可能移除關鍵小目標，需以相同資料切分比較任務指標，並檢查不同目標尺寸的錯誤。看來乾淨不等於保留了有用訊號。

## 梯度邊緣與閾值

**題目：** 將 `[100,20]` 做前後差分得到 -80，為什麼直接把負數設 0 會漏掉一側邊界？兩張圖一張較暗，固定亮度門檻是否仍公平？

## 二值化連通元件與形態學

**題目：** 5 個螺絲經膨脹後只剩 3 個連通元件，是螺絲少了嗎？一個像素點做  $3\times 3$  方核開運算後消失，可以直接稱為雜訊嗎？

## 影像處理練習與解析

# 影像處理練習與解析

用手算、反例與比較實驗，驗收色彩、縮放、濾波、邊緣及連通元件流程。

## 練習不以圖像漂亮為標準

前處理的目標是保留任務需要的訊號並維持資料契約。每題先寫會變與不應變的量，再執行小型驗證。例如 resize 可以改變像素數，但不應產生不存在的 mask 類別；平均可以降低局部極端值，但不保證保存細線。答案必須包含條件，不能只說某方法通常比較好。

這組題目故意使用常數圖、色塊、單點及簡單矩形，因為它們的預期值能手算。真實照片適合後續檢驗效能，卻可能讓錯誤被複雜紋理遮住。先把基本運算驗證清楚，再把同一流程套到未見情境。

## 題目一：灰階與色彩訊息

一個 RGB 像素是 `(200,20,20)`，若示範式採 `Y'=0.299R'+0.587G'+0.114B'`，灰階約多少？把資料轉灰階後再複製三通道，是否能讓模型重新取得紅綠差別？

**解析：**  $59.8+11.74+2.28=73.82$ ，轉成 8-bit 時約為 74，具體取整依實作。複製三份只改輸入形狀，不會找回丟失的顏色訊息。若類別的差別依靠色相，應保留色彩並檢驗相機及照明變化。該公式描述編碼值的灰階近似，不能拿來不加條件地量測物理亮度。

## 題目二：等比例補邊

原圖  $160\times 80$  要放入  $96\times 96$ ，框為 `(20,10,100,60)`。計算縮放比例、新尺寸、對稱 padding 與新框；若模型在新圖預測 `(12,30,60,60)`，如何回到原圖？

**解析：** 比例 0.6，縮成  $96\times 48$ ，上下各補 24；新框為 `(12,30,60,60)`。反向去掉 y padding，再除以 0.6，得到原框。此處尺寸恰好整數，沒有取整差異；一般情況需保存實際新寬高與每邊 padding。若直接把新框乘 `160/96`，y 方向會把補邊一起放大，得到錯誤位置。

## 題目三：mask 的插值

某 mask 只有左右兩類，ID 分別為 0 與 2。放大後邊界出現 ID 1，是模型發現了第三類嗎？若只在最後 `round()`，是否已修好？

**解析：** 它可能是雙線性插值把 0 與 2 混成 1，原標籤沒有第三類；最後四捨五入仍可能保留 1，並不能保證回到合法集合。硬標籤採最近鄰，變換後檢查 unique ID 是否屬合法集合，加上專門的 ignore 值。若研究的是軟標籤，需另定連續 target、loss 與評估，不應與硬 mask 混用。

## 題目四：邊界與平均

所有像素均為 90 的影像，以  $3\times 3$  平均核計算左上角。補零時答案多少？複製邊界時呢？若平均核沒除以 9，內部輸出又是多少？

**解析：** 補零只有四個有效像素，結果  $\frac{360}{9}=40$ ；複製邊界維持 90。未正規化 kernel 則內部輸出  $9\times 90=810$ ，若存 uint8 可能飽和，掩蓋真正計算結果。不要只根據輸出「看起來仍是白色」判斷正確，應用浮點數值檢核及已知輸入確認。

## 題目五：邊緣與元件

暗亮暗條帶的 x 梯度應含哪些符號？把邊緣圖的連通元件數量當作物體數，會有哪些失敗情境？

**解析：** 暗到亮可為正、亮到暗可為負；直接丟負值會漏一邊。邊緣可能斷裂，一個物體分成多元件；兩物體可能因陰影或相碰而連接；紋理會新增邊緣。邊緣線不是填滿區域，更沒有直接提供個體身分，需要適合的區域處理、額外假設或實例模型。

## 題目六：連通性與尺度

兩個前景像素只在角落相碰，4-連通與 8-連通各幾群？同一個  $3\times 3$  核可否在解析度加倍後視為完全相同的實際處理？

**解析：** 分別為兩群與一群。解析度加倍後，同樣像素核在物理場景中覆蓋較小範圍；若目的依毫米尺度清除小物，應先校正或根據比例調整，再驗證邊界效應。不能只把 kernel 大小機械式加倍就宣稱結果等價，因為離散化及形狀也可能改變。

## 整合挑戰：建立可反駁的比較

建立含圓、細線、椒鹽點與接近邊界矩形的合成圖，另外產生不同曝光與解析度版本。比較「無前處理、平滑、閾值加開運算」三條流程，預先列出對小目標、面積及計數的期待。保留所有中間圖和參數；如果某流程去掉噪點同時漏掉細裂紋，要把兩種效果一起呈現。

進入真實資料後，從訓練／驗證集選參數，測試集留待最後；不挑最漂亮的單張圖作為唯一證據。最終結果至少包含失敗圖、目標尺寸及照明分組，讓「有效」的主張有明確適用範圍。

## 以可檢查產物作答

資料工程練習的答案不只是一行模型程式。請準備類別映射、split manifest、稽核清單、增強疊圖與批次 shape 記錄。每一項都能對應到資料版本與樣本身分，才有辦法在模型結果變動時查出原因。以下案例是人工設定的教學情境，與真實資料集效能無關。

作答時先問「希望泛化到什麼」，再問「哪些資料能參與這個選擇」。後者涵蓋切分、均值、門檻、類別權重、標註修訂與增強調整。把 test 欄位保留在 CSV 裡並不代表已防止洩漏；實際程式讀了哪些列才是關鍵。

## 題目一：定義新物件測試

100 個實體零件，每個拍攝 10 張，共 1000 張。需求是在新零件上辨識外型。先對每張圖旋轉產生 5 份，再隨機切成 train／val／test，有什麼問題？修正後是否一定每類都有測試樣本？

**解析：** 原圖、衍生圖與同一實體零件的近似照片可能跨集合。應以原始零件 ID 群組切分，再只在 train 端增強。是否每類都有獨立群組取決於原資料；某類若只有一個零件，不能拆開它來假裝同時有獨立訓練與測試。要補資料或明列該類泛化無法估計，而不是只追求表面比例。

## 題目二：ID 與空目標

分類  `circle=0` 、 `rectangle=1`  的映射可以原封不動送進本課偵測 API 嗎？一張沒有物體的影像是否應標一個 `[0,0,0,0]` 框、 `label=0` ？語意 mask 的 0 又是否一定要忽略？

**解析：** 本課偵測前景從 1 起，0 保留背景，需有明確任務映射。空圖使用 `(0,4)` boxes 與 `(0,)` labels，不是假造零面積背景框。語意分割的 0 是合法背景類，255 才是本課 ignore；分類與分割不能照抄偵測的背景保留規則。映射和 ignore 政策都要保存及驗證。

## 題目三：統計量與偷看答案

你先讀完全部影像計算 RGB 均值、標準差，再建立切分，認為沒有使用 label 就不算洩漏。問題在哪？若改用預訓練權重提供的 transforms，是否也等同從 test 計算？

**解析：** 全部影像包含測試分布，資料驅動的前處理已利用測試資訊。通常應先切分，只從 train 估計統計量。使用事先固定的外部權重前處理是不同情況，沒有由本次 test 重新估計，但需記錄來源並檢查是否適合任務；仍不能用 test 成績反覆選擇各種前處理。例外如明定的 transductive 協定需另外說明，不能默默混入一般未見評估。

## 題目四：共同增強

寬 100 的圖，框 `(10,5,30,25)`，影像做水平翻轉但 mask 沒翻。請寫新框並說明如何設計一個能抓出錯位的測試。只檢查框仍在畫布內是否足夠？

**解析：** 新框是 `(70,5,90,25)`。建立已知前景矩形的合成圖，把 image、框與 mask 共同傳入確定翻轉，再比對框邊界、mask 前景範圍與影像前景。只檢查框合法不足，錯位框也可能完全在畫布內。隨機增強測試可先固定參數驗幾何，再檢查隨機流程，避免測試自己也不穩定。

## 題目五：資料載入與樣本總數

測試集有 23 張，batch  `size=8` ， `drop_last=True` 。某張壞檔在 Dataset 裡被替換成上一張，程式仍跑完。這兩項選擇如何改變評估？Windows 將 num_workers 從 0 改 4 又可能遇到什麼？

**解析：** drop_last 只評估 16 張，另外 7 張未計入；替換壞檔使樣本身分與答案不再對應，且重複了別張的權重。應先稽核並依政策處理壞檔，評估涵蓋所有合法樣本。Windows 多進程需 main guard、頂層可序列化函式，還可能出現記憶體與啟動成本；不是 workers 越多就必定越快。

## 題目六：雜湊與近重複

兩張圖看起來相同，但 JPEG 品質不同，檔案 SHA-256 不同。是否已證明它們是獨立樣本？如果感知相似度很高，是否可以自動刪除其中一張？

**解析：** 檔案 hash 不同只表示 bytes 不同，不能排除重新編碼或裁切副本。可追加像素與感知層級檢查、來源追蹤及人工覆核。高相似度也不必然是重複，標準零件本來可能很像；先判斷群組與資料來源，再決定隔離或刪除政策，保留可追溯紀錄。

## 整合挑戰與完成標準

用自行產生的圖建立至少三個群組，包含一張空目標、一張貼邊目標、一個含 ignore 的 mask 與一個故意壞掉的檔案。產出合法清單、切分表及疊圖，檢查群組不相交、非法 ID 被攔截、壞檔被記錄、增強後目標同步、最後一批不被丟掉。

## CNN如何看見局部與空間

輸入高24、kernel3、padding1、stride2，輸出高為12。若dilation2，輸出則為11。參數量不因stride變化，但輸出格數改變，計算量會變。把padding改為0時，不應只改全連接層數字；先印出各層shape，確認邊界訊息的改變符合任務需要。

小型範例以CPU完成張量與算術驗證。GPU可加速訓練，但不會修正HWC／CHW、尺寸或標籤錯誤。

## 從零訓練影像分類器

將全部訓練標籤改為0，loss仍可能快速下降，但已不再學兩類問題。驗證集若保留兩類，正確率約受多數類別限制。再將lr提高十倍，若loss震盪，先還原基準，再檢查梯度及數值範圍。一次改多個設定會讓原因難以歸屬。

延伸任務是把輸出、版本、資料種子及前處理寫成實驗紀錄；不要把訓練畫面截圖當作可重現交付。

## 準確率之外的分類評估

真0有90張全對，真1有10張全錯。accuracy90%，balanced accuracy50%，macro recall50%。這不是指標衝突，而是平均問題不同。若只看accuracy，會忽略所有瑕疵；若只看macro，仍不知道實際誤報量，兩者應配合支持數與成本說明。

門檻只能在開發資料上選。看了測試錯例再修改門檻，下一次就需要新的保留評估資料。

## 模型學不動時如何逐步定位

訓練準確率100%，驗證50%，能斷言模型太大嗎？不能。標籤對照表在兩個資料夾互換，也會出現這個結果。先檢查兩份class_to_idx，再看資料來源差異，最後才談容量與正則化。

如果BatchNorm在驗證階段仍更新running stats，結果會隨驗證順序改變。正確操作是eval()，並避免驗證資料改變模型狀態。對無法解釋的高分，也要做標籤打亂與背景遮蔽等負向檢查，找出捷徑學習或洩漏。

# 分類實作練習與完整解析

## 題目：追蹤張量與參數

輸入[4,3,32,32]， `Conv2d(3,16,3,stride=2,padding=1)` ，接ReLU及AdaptiveAvgPool2d(1)，最後Linear(16,5)。寫出每步shape與卷積參數量，說明為何不需要在每次換batch大小時重建Linear。

解析：卷積為[4,16,16,16]；ReLU不改shape；池化為[4,16,1,1]，flatten(1)後[4,16]；輸出[4,5]。卷積參數 $16\times (3\times 3\times 3+1)=448$ 。batch軸不是Linear輸入特徵軸，因此最後一批只剩1張仍可推論，但訓練時其他層如BatchNorm可能有額外限制。

## 題目：損失函數契約

五類單標籤問題，輸出[8,5]，標籤寫成[8,1]的float，能直接送入CrossEntropyLoss嗎？

解析：本課整數類別模式要用[8]、long且值為0到4；不把標籤除255，也不必手動one-hot。另一種機率目標模式是不同用途，不能用形狀湊合來替代。損失輸入維度合法，也仍需檢查標籤語意。

## 題目：比較兩個模型

## 分類定位與匹配損失

## 一個總loss包含不同的學習問題

分類要回答「是什麼」，定位要回答「框在哪裡」，候選機制可能還要回答「是否值得仔細看」。因此偵測訓練常回傳多項loss，而不是單一分類交叉熵。不同模型的項目名稱與尺度不一樣，先閱讀該模型文件與原始碼，再決定怎麼加總與紀錄。

一個抽象寫法是$L=L_{cls}+\lambda L_{box}$；兩階段模型另有proposal相關項目。這是理解結構的記號，不是要求所有模型固定只有兩項。權重 $\lambda $ 改變「一單位定位誤差相對分類誤差有多重要」，會改變最佳化路徑；觀察到數字較大的項，也不能僅憑大小就判定它最重要。

## 先有責任分配，才有正確梯度

某個預測框要對哪個真實框計算損失？anchor或格點方法可能用IoU、位置或動態規則指派正負例；集合模型使用整體匹配。沒有被指派為前景的候選，通常不應拿任意真實框來做定位迴歸。資料有兩個物件，不代表所有數千個候選都要往其中一個框靠近。

例如A、B兩個目標與兩個query的匹配成本為`[[1,4],[2,3]]`，一對一最小總成本是4。若對每列各自選最小值，兩列都選A，B就沒有負責者。匹配成本用於選擇分工；真正反向傳播的損失仍需依架構定義，不應將離散指派索引當作可微連續輸入。[DETR配對設計](https://arxiv.org/abs/2005.12872)是此處的原始背景。

## 分類與容易背景

對一個真實正例，模型給正類機率0.9時，交叉熵約0.105；給0.1時約2.303。若有上萬個機率0.99的容易負例，單筆loss小仍可能加總成顯著梯度。Focal Loss以$(1-p_t)^\gamma$調節容易樣本的權重； $\gamma =2$ 時，$p_t=0.9$的乘數0.01，$p_t=0.1$的乘數0.81。這個數值例子解釋調節方向，完整公式還可能有類別權重。

不要把Focal Loss當作增補少數類資料的替代品。若某一類從未被標註，模型沒有正確監督；若同樣外觀有時標前景有時漏標，調高難例權重甚至可能更強調矛盾樣本。[Focal Loss原論文](https://arxiv.org/abs/1708.02002)說明其密集偵測背景。

## 定位損失與座標尺度

直接L1對每個座標差取絕對值；Smooth L1在小誤差區域更平滑。對大框偏移2像素和小框偏移2像素，座標L1可能相同，實際重疊品質卻不同。IoU類損失用區域關係度量差異；普通IoU在完全不相交時缺乏區分距離的訊號，GIoU另考慮最小包覆區域。各方法的梯度與尺度不同，不能僅換函式名就假定訓練超參數仍最適合。

若某框標註是正規化0到1，而模型預期像素0到1024，所有定位誤差的量級都會錯。先印出幾張圖的target與預測，確認範圍與面積，再調 $\lambda $ 或學習率。[GIoU原始論文](https://arxiv.org/abs/1902.09630)與[torchvision generalized_box_iou_loss](https://docs.pytorch.org/vision/stable/generated/torchvision.ops.generalized_box_iou_loss.html)分別提供思想與介面。

## 訓練診斷與練習

紀錄每項loss、有限值檢查、正例數量、梯度大小與固定驗證圖。先讓極小資料集過擬合，確認資料與反向流程可學；再回到完整切分與正則化。訓練loss下降不保證AP上升：分數排序、框定位與類別錯誤都會影響AP。

練習：分類loss從0.8降至0.2，框loss從0.1升至0.5，總loss一樣，能說模型沒有變化嗎？不能。它可能更會分類卻更不會定位。至少比較兩項loss、 $\frac{\mathrm{AP}50}{\mathrm{AP}75}$ 及固定圖的框，才知道改變的實際結果。若所有loss都NaN，優先查無效框、非有限輸入與錯誤數值尺度，再考慮最佳化器。

## 信心門檻與非極大值抑制

如果A與B的IoU剛好等於門檻0.5，Torchvision的`nms`是否抑制B？API定義為大於門檻才抑制，所以僅等於不會因這個條件被刪。浮點接近邊界時仍要以實際精度驗證。這也說明測試不能只驗證0.8這種遠離邊界的例子。

進一步設計四類案例：不同類但重疊、同類且重疊、完全不相交、完全同分。把保留索引、分數政策與類別策略寫在預測檔metadata，之後才有辦法比較版本。

## 物件偵測練習與解析

## 先建立自己的驗收表

這一章的目的不是記住一個模型名稱，而是能檢查一份偵測資料與預測結果。開始前在紙上列出：原圖尺寸、框格式與邊界規則、類別ID、資料切分群組、轉換順序、空圖表示、模型輸入輸出、分數與NMS政策。缺少其中一項，後面的模型分數就可能難以解釋。

以下題目全部是原創小型算例，請先手算，再用本課範例交叉檢查。它們驗證概念與介面，不是COCO benchmark，不可拿計算結果宣稱某個大型模型達到多少mAP。

## 題目一：同一個數列，兩種不同框

標註檔的一列是`[10,20,30,40]`。甲說它的面積是400，乙說是1200。誰對？

**解析：**若它是XYXY，寬20、高20，面積400；若是XYWH，寬30、高40，面積1200。只看四個數字不能判定誰對，必須回到格式契約。若資料來源沒寫格式，先用多張原圖與標註工具驗證，不能只以「數值看起來合理」猜測。建立匯入器後，保存來源格式與轉換版本，並保留一組已人工確認的圖作回歸檢查。

延伸：把XYWH正確轉成XYXY應為`[10,20,40,60]`；它的右下界不是原列表第三、四欄。當 $W=100$ 、 $H=80$ 時，中心正規化為`[.25,.5,.3,.5]`，請逐項說明分母。

## 題目二：裁切後只剩半個物件

原圖 $W=100$ 、 $H=80$ ，框`[70,20,100,60]`。裁切視窗取x從50到90、y從10到70。新圖尺寸與框是多少？

**解析：**新圖寬40、高60。先減去裁切原點，框成為`[20,10,50,50]`；裁到畫布後為`[20,10,40,50]`，面積800。是否保留只剩部分的物件，取決於已明定的可見率與最小面積政策；不能在train一律保留、validation卻未記錄地刪掉。若移除該框，labels、masks與其他逐物件欄位也必須同步刪除。

延伸：水平翻轉新圖，框成為`[0,10,20,50]`。若寫成`[40-20,10,40-40,50]`就會倒置，顯示你沒有交換左右邊界。請用同一張圖畫出裁切前後與翻轉後三個畫布。

## 題目三：背景不是一個零面積物件

資料集把沒有目標的照片寫成 `boxes=[[0,0,0,0]], labels=[0]` ，模型報無效框。應如何修正？

**解析：**明確無目標的照片用空`[0,4]`框與空`[0]`labels；label 0在本課偵測器契約中保留為背景，並不是要求每張圖標一個背景物件。若照片其實是「尚未標註」而非「確認沒有目標」，則不能直接當負例，應送回標註流程或排除訓練。這兩種缺失語意會產生截然不同的監督。

檢查時同時問：空圖是否被資料載入器保留？batch能否容納不同框數？資料切分是否把同一影片的空幀與有物件幀分散兩邊？這些都不是換loss函式就能補救的問題。

## 題目四：NMS與評估不要混為一談

真實圖只有一個人。模型輸出三個同類框，分數0.9、0.8、0.7，前兩個高度重疊且位置正確，第三個在空白區。將NMS門檻降低後只刪掉第二個，第三個仍存在。為什麼？

**解析：**NMS處理相互重複，不知道真實標註；第三個與其他框不重疊，所以不會被刪除。它仍可能是FP，需要模型、分數門檻或資料品質改善。若第二個框其實是另一個靠近的人，過強NMS反而可能刪掉真實物件。因此必須在固定驗證資料比較漏報、誤報與重複，不能只看框數減少就認為進步。

## 題目五：匹配與學習

兩個query都最喜歡同一個真實框，另一真實框沒有被選中。逐列取最小成本是否等同一對一匹配？**不是。**一對一匹配要對整體合法指派比較總成本；模型責任分工不能讓兩個預測同時消耗同一個一般真實目標。訓練指派與評估配對雖都使用「匹配」一詞，其輸入、目的與規則仍須分開紀錄。

## 可交付成果與參考

完成後交出一頁資料契約、三張疊圖、框格式往返測試、空圖測試與NMS保留索引表。若其中一項還無法解釋，先回該單元修正，再開始正式訓練。介面可回查[偵測資料教學](https://docs.pytorch.org/tutorials/intermediate/torchvision_tutorial.html)，幾何轉換查[torchvision transforms](https://docs.pytorch.org/vision/stable/transforms.html)。

## 一對一匹配與重複預測

沿用四筆預測，把評估IoU門檻提高到0.75。p1的0.8仍為TP；p2對A已重複且0.7不足；p3的0.6不再達標，變FP；p4仍FP。結果 $\mathrm{TP}=1$ 、 $\mathrm{FP}=3$ 、 $\mathrm{FN}=1$ ， $\mathrm{precision}=0.25$ 、 $\mathrm{recall}=0.5$ 。模型與分數都沒改，評估要求變嚴格，因此分數改變。

請在預測表增加`matched_gt_id`與`reason`欄，區分重複、類別、定位和背景；同時留存原始框，讓其他人可以獨立重算。正式資料的ignore與crowd要依[COCOeval原始碼](https://github.com/cocodataset/cocoapi/blob/master/PythonAPI/pycocotools/cocoeval.py)處理；不要在教學配對器上貼上COCO名稱。

## PR曲線與AP的計算

## 一個工作門檻只提供曲線上的一個點

將分數門檻從高往低放寬，通常會保留更多預測，召回逐步增加，precision則可能升也可能降。PR曲線把這一串可選操作點排出來。AP用某種明定的方式摘要整條曲線，因此必須交代插值與積分規則，不能只寫一個沒有口徑的「AP」。

部署可能只在某個固定門檻運作，此時要同時報該門檻的precision、recall、每圖誤報與漏報成本。整體AP高的模型，不一定在你要求的低誤報區間最好；選模型與選操作點是相連但不同的決策。

## 排序表的原創算例

假設只有兩個真實目標，已依前一單元的規則配對，五筆預測由高分到低分的結果是`TP, FP, TP, FP, FP`。每次多收下一筆，計算累積TP與FP：

| 排名 | 結果 | 累積TP | 累積FP | Precision | Recall |
| --- | --- | --- | --- | --- | --- |
| 1 | TP | 1 | 0 | 1 | 0.5 |
| 2 | FP | 1 | 1 | 0.5 | 0.5 |
| 3 | TP | 2 | 1 |  $\frac{2}{3}$  | 1 |
| 4 | FP | 2 | 2 | 0.5 | 1 |
| 5 | FP | 2 | 3 | 0.4 | 1 |

Recall的分母是真實目標數2，不是五筆預測。末端precision變差並沒有創造新召回；這正是重複框與背景誤報仍需要檢查的原因。

## 本課玩具AP：precision envelope的面積

對每個召回位置r，取其右側可達的最大precision，得到向右看齊的包絡線$p_{interp}(r)$。在此算例中，0到0.5的高度為1，0.5到1的高度為 $\frac{2}{3}$ ；面積為 $0.5\times 1+\frac{0.5\times 2}{3}=\frac{5}{6}$ ，約0.8333。這是本課連續區間面積的玩具AP，不是COCO的101個recall點平均。

$$
AP_{toy}=\sum_i (r_i-r_{i-1})\,p_{interp}(r_i)
$$

只有召回真正增加的步驟才產生面積；其間的FP會降低後來能達到的precision。若最後只能找回一半真實物件，剩餘召回區間按本協定為0，不能把曲線終點後方補成最後一次precision。

## 改變排序，比單純改分數更重要

把五筆預測的分數都經過嚴格遞增函式變換，只要排序與可用預測沒有改變，這個AP便不變；但固定數值門檻留下的預測可能改變。反之，若誤報升到第一名，即使真實框座標完全不變，AP也會下降。因此「分數看起來更高」不代表排序或校準更好。

可以用最小對照測試驗收AP計算：完美排序且全部檢出應為1；所有預測都錯應為0；在高分前端插入FP應降低AP；在召回已到1之後加低分FP，在本包絡線面積定義下可能不改AP。最後一點不代表這些誤報沒成本，只說明AP沒有平均每個操作點的錯誤。

## 不同AP定義不能混報

COCO、歷史VOC版本與其他領域可能使用不同插值或平均政策；分類的average precision也有自己的樣本定義，不能只因名稱相似就拿同一個函式當偵測評估器。偵測要先完成空間與類別配對，之後才有排序的TP/FP序列。比較兩個系統時，必須使用同一資料、同一IoU門檻、同一預測上限與同一套評估程式。

練習：若排序改為`FP, TP, TP`、仍有兩個真實物件，本玩具AP是多少？累積precision為0、 $\frac{1}{2}$ 、 $\frac{2}{3}$ ，包絡線在0到1皆可達 $\frac{2}{3}$ ， $\mathrm{AP}=\frac{2}{3}$ 。請比較這與 $\frac{5}{6}$ 的差異，說明第一個高分誤報如何影響整條排序。

## COCO評估與mAP定義

## 「mAP 50」這句話不夠完整

先分清楚數值50%、IoU門檻0.50與多門檻平均三種意思。報告應寫明例如`COCO bbox AP @[.50:.95]`或`bbox AP50`，並附資料切分與評估器版本。AP50比較寬容；AP75對定位要求較高，兩者差距大時值得檢查邊界、縮放還原與小物件。

COCO常用bbox摘要在多個IoU門檻、類別與101個召回取樣點上彙整：IoU從0.50到0.95、間隔0.05。另有大小範圍與每圖最大預測數等維度，常見主摘要使用 `maxDets=100` 。沒有有效真實標註的類別或切片，不應任意當成一般0分加入平均。具體ignore、crowd、area與有效項目規則以指定版本的[官方COCOeval程式](https://github.com/cocodataset/cocoapi/blob/master/PythonAPI/pycocotools/cocoeval.py)為準。

## 用兩類玩具數字理解平均維度

以下僅示範平均的概念，不是完整COCO評估。假設類別A在IoU0.5的AP為0.9、0.75的AP為0.6；類別B分別0.5、0.2。只平均兩類的AP50得到0.7；只平均兩類的AP75得到0.4；再把這兩個門檻一起平均得到0.55。三個數都可由同一份預測算出，但回答的問題不同。

實際COCO主AP不是只用這兩個IoU門檻，也不是拿不同門檻下的TP總數相加再除以全部預測。每個條件先產生相應的配對與PR評估，再按協定彙整；不能使用此例的0.55對外宣稱COCO AP。

## bbox、segm與keypoints是不同任務

一份實例分割預測可以同時輸出框與遮罩，但框的重疊好不代表遮罩貼合輪廓。`iouType="bbox"`與`"segm"`使用不同區域；keypoints另有與可見性、尺度相關的OKS。若報告只寫「模型AP」，讀者可能不知道你評估了什麼。模型名稱相同，也不能直接跨任務比較數字。

資料格式也要分清楚。本課內部常用XYXY；COCO bbox結果檔使用XYWH。將`[10,20,40,60]`的XYXY直接寫成COCO bbox，評估器會把40、60當成寬高，產生另一個矩形。category_id要回到資料集原始編碼，image_id要對上同一份annotations，而不是DataLoader的順序索引。

## 正式評估的可重算流程

先凍結資料清單與標註版本，再將模型輸出還原到原圖座標；保存image_id、category_id、bbox或segmentation、score以及必要metadata。使用官方評估器時明確指定任務與參數，保留逐類／逐尺寸結果及summary。若調整maxDets或area範圍，報告名稱應標示自訂，而不能與未調整的表格無縫混排。

```text
資料清單與標註雜湊
    → 模型版本＋前處理／後處理契約
    → 原圖座標預測檔
    → 指定版正式評估器＋完整參數
    → 整體摘要＋各類／大小切片＋失敗圖
```

預測檔應可獨立交給另一人重算；若只存一張summary截圖，無法判定分數差異來自模型、資料、格式轉換還是評估設定。對測試集反覆調門檻會破壞最終評估的獨立性，選擇應在驗證集完成。

## 邊界與忽略政策

擁擠或未完整標註的區域可能採不同配對政策。只把所有iscrowd設0以求程式能跑，不會保留原本協定；簡化教學配對器也不足以驗證這些情境。使用自建資料時，先定義哪些物件確實應被算作可檢出目標、哪些區域不參與評分，再選擇支援該契約的評估方式。

練習：模型X的AP50較高、AP75較低，能否直接說X全面較好？不能。它可能更容易找到大概位置，但框不夠精準。至少看完整IoU平均、各類與大小表現，並依使用需求判斷。若差異只出現在小物件，還應檢查每個切片的樣本數與標註一致性。

## 小物件遮擋與定位錯誤

## 平均分數下降，先找錯誤在哪裡

偵測錯誤不只有「預測錯」。一個框可能類別對、位置略偏；也可能位置對、類別錯；同一物件可能輸出三次；空背景可能被誤認；真實物件也可能完全沒有候選。改善方法取決於錯誤來源，沒有一個超參數可以同時修好所有類型。

建立失敗表時保留原圖、真實框、分數、原始預測與匹配結果。先按可觀察原因分類，再設對照實驗；不要直接把所有低IoU都說成「模型不夠大」。[TIDE原始研究](https://arxiv.org/abs/2008.08115)提供把偵測錯誤細分的思考背景，本課的排查表則是教學用簡化版本，不冒稱正式TIDE輸出。

## 為何兩像素對小物件更嚴重

真實框A是 $4\times 4$ ，沿x偏移2像素後，交集是 $2\times 4=8$ ，聯集24， $\mathrm{IoU}=\frac{1}{3}$ 。若改成 $40\times 40$ 物件，同樣偏移2像素，交集 $38\times 40=1520$ ，聯集1680，IoU約0.905。相同絕對偏移對小物件造成更大相對誤差，這是幾何效果，不需要先假設哪一種網路比較差。

縮小原圖後，小物件可能只剩幾個像素；即使後來放大，細節也不會自動恢復。改善時可比較輸入解析度、多尺度特徵、合適裁塊或較密集的特徵格點，但同時測記憶體、延遲、重複框與切塊邊緣漏檢。切塊後的同一原圖應維持在同一資料切分群組。

## 遮擋先回到標註政策

一個被桌子擋住下半身的人，到底標可見身體還是估計完整身體？兩種任務都可能合理，但不可混標。嚴重遮擋與截斷應有可見性或品質欄位，避免把不可判定答案一律當一般標註。標註者之間的差異也可能限制高IoU門檻下能達到的分數。

若兩個同類物件靠得很近，NMS可能誤刪其中一個。先畫出NMS前與後的框，看真實物件是否在前一步就有候選；若沒有，調NMS也救不回來。反之，若候選原本正確卻被刪，才考慮後處理策略與擁擠情境的門檻驗證。

## 切片的樣本數與選擇偏差

依物件大小、遮擋、相機、光線、拍攝距離切片，可找到平均分數藏住的弱點；但每個切片要附樣本數與標註政策。只有三個夜間物件的高分，不能支持所有夜間場景可靠。看過test失敗後反覆挑資料或調參，會讓test逐漸成為validation，應另保留最後確認資料。

練習：提高解析度後AP小幅上升，延遲加倍，能否直接採用？先看真正需要改善的切片是否受益、信賴程度與目標硬體預算，再比較較便宜的資料修正或切塊方案。若只是大物件再改善而小物件仍漏，這個改動可能沒解決原問題。

## 偵測評估練習與解析

## 題目一：重複框算幾次

資料中有兩個真實目標A、B。依分數排序，p1匹配A，p2也在A附近，p3匹配B；皆為同類，IoU皆達門檻。三筆預測的TP/FP序列、末端precision與recall是多少？

**解析：**一般非crowd的一對一教學規則得到`TP,FP,TP`。末端 $\mathrm{TP}=2$ 、 $\mathrm{FP}=1$ ，因此 $\mathrm{precision}=\frac{2}{3}$ 、 $\mathrm{recall}=1$ 。p2不能讓A再得一次分。若你的計算器得到 $\mathrm{recall}=1.5$ ，表示它允許重複消耗真實目標，或使用了錯誤分母。把每筆配對的真實ID輸出，就能直接看出違規。

延伸：若把p2刪除，召回不變、末端precision變1；若p2其實是另一張圖的預測，則不得與本圖A配對，必須回到自己的image_id檢查。分數排序前保留原始識別碼比只留四個座標更有用。

## 題目二：玩具AP與COCO不是同一個數

兩個真實目標，排序為`TP,FP,TP`，請使用本課precision envelope連續面積定義計算AP。

**解析：**召回在第一個TP到0.5，precision為1；第二個TP到1，precision為 $\frac{2}{3}$ 。面積是 $0.5\times 1+\frac{0.5\times 2}{3}=\frac{5}{6}$ 。若只平均三次precision，得到`(1+1/2+2/3)/3`，那不是本課指定的AP積分。

即使答案 $\frac{5}{6}$ 算對，也不能報成COCO AP。正式COCO使用101個召回點以及多IoU、類別等設定；需要指定評估器產生完整結果。報告要寫`toy envelope AP @ IoU .5`這類明確名稱，並讓讀者知道沒有crowd、ignore與正式切片。

## 題目三：大小相同的偏移，影響不同

一個 $10\times 10$ 框沿x偏移2像素，另一 $100\times 100$ 框也偏移2像素，哪個IoU較小？

**解析：**小框交集80、聯集120， $\mathrm{IoU}=\frac{2}{3}$ ；大框交集9800、聯集10200，IoU約0.9608。因此即使同樣座標誤差，小物件在高IoU門檻下更容易失分。不能只用平均座標L1推論不同物件大小的定位品質一致。進一步可比較尺寸切片、原始像素大小與標註邊界一致性。

若提高解析度，需讓真實框與預測共同轉換，並把評估回到原圖座標。只將預測乘2而標註不動，並不是解析度實驗，而是人為製造座標錯誤。

## 題目四：一份看似漂亮的成績單

同事的報告寫「準確率95%，模型已可部署」，附了三張挑選照片。你還需要哪些證據？

**解析：**先問任務與分母：95%是分類accuracy、某門檻precision、AP50還是多IoU平均？接著看資料來源、群組切分、各類物件數、空圖、標註政策、模型與權重、前後處理、評估器版本。最後需要固定門檻下的漏報與誤報成本、目標硬體延遲、失敗切片與部署後的監控。

三張展示圖可以說明模型輸出形態，不能代表抽樣性能。若同一影片的相鄰幀進入train與test，或門檻在test上反覆調到漂亮，應重新安排獨立評估，而不是只多放幾張成功圖。

## 題目五：沒有真值與沒有預測

甲類在test沒有任何真實標註；乙類有十個真實物件，但模型完全不輸出。兩者都寫 $\mathrm{AP}=0$ 是否足夠？

**解析：**乙類確實漏檢全部目標；甲類則無法用該切分估計該類召回與AP，應依評估器有效項目政策標示不可用，另報其預測誤報。把不可估計當普通0加入平均，可能改變整體分數。資料不足本身是發現，應補足代表性測試資料，而不是默默隱藏。

## U-Net與多尺度跳接

## 分類架構為何不能只換一個標籤

分類常把空間特徵壓成一個向量，適合回答整張圖的類別；分割需要每個位置的答案，過度壓縮會丟掉精細邊界。U-Net提供直觀的編碼器與解碼器結構：往下累積較大範圍的語意，再往上恢復解析度，並把較早層的細節傳給後段。

[U-Net原始論文](https://arxiv.org/abs/1505.04597)於2015年提出經典收縮／擴張路線。原始實作的valid卷積、裁切與今天常見same-padding變體不完全相同；本課用小型same-padding模型解釋shape，不能把它的尺寸表當成原論文所有層的精確複刻。

## 一條可手算的shape路徑

輸入`[N,3,64,64]`。第一個卷積區塊輸出`[N,16,64,64]`，池化後`[N,16,32,32]`；第二區塊變`[N,32,32,32]`，再池化到 $16\times 16$ ；瓶頸輸出`[N,64,16,16]`。這裡空間變小、通道增加，是一種設計選擇，不是數學上必須每次都剛好加倍。

第一個上採樣把瓶頸變`[N,32,32,32]`，與同尺寸的encoder特徵沿channel串接，得到`[N,64,32,32]`；卷積再整合成32通道。下一層上採樣到 $64\times 64$ ，與16通道skip串接，再輸出16通道。最後 $1\times 1$ 卷積把每個位置映射成C個類別logits，得到`[N,C,64,64]`。

## concatenate與residual addition不同

U-Net常見skip是串接：空間尺寸相同，通道數相加，後面卷積學習如何混合來源。ResNet常見shortcut是相加：兩支輸出形狀需一致，通道不會因相加而翻倍。兩者都幫助資訊流通，但不能把程式的`torch.cat`直接換成`+`而不調整通道設計。

```python
import torch

decoder = torch.zeros(2, 32, 32, 32)
skip = torch.zeros(2, 32, 32, 32)
combined = torch.cat([decoder, skip], dim=1)
assert combined.shape == (2, 64, 32, 32)
assert (decoder + skip).shape == (2, 32, 32, 32)
```

skip帶來細節，也可能帶入背景紋理與資料捷徑；模型仍需獨立驗證。架構有skip不保證邊界一定準確，標註品質、輸入解析度與損失設計都可能是限制。

## 奇數尺寸與上採樣政策

若輸入 $65\times 65$ ，連續pooling可能變 $32\times 32$ 再 $16\times 16$ ，單純乘2上採樣只能回 $64\times 64$ ，與最早skip的 $65\times 65$ 不符。常見策略包括先補到可整除尺寸、裁切skip、明確插值到skip尺寸，或設計轉置卷積的output_padding。每種方法都影響空間對齊，應在資料契約中固定，不能每次遇到錯誤就隨意切掉一列。

插值上採樣後接卷積與轉置卷積各有計算與形狀特性。若使用bilinear插值，需要明確固定`align_corners`等參數，並以已知位置的小方塊驗證對齊。最終輸出回原圖也應保存padding與crop政策，避免訓練與部署相差一個像素。

## 訓練前先做三個檢查

第一，輸入不同批次與奇偶尺寸，確認輸出與target空間大小一致。第二，給極小原創資料集，檢查loss能下降、梯度有限且前景可被學到。第三，檢查eval輸出的argmax與原圖疊圖，不只看loss曲線。若全部輸出背景，先查mask值域與類別不平衡，再考慮把網路做得更深。

練習：decoder有24通道、skip有16通道，串接後接的卷積應設定多少input channels？答案40。若卷積仍設24會shape錯；若使用相加則也不相容，需投影或其他明確設計。把每層shape寫成一張表，通常比隨機更改參數更快找到錯誤。

## 原始介面與限制

串接介面見[torch.cat](https://docs.pytorch.org/docs/stable/generated/torch.cat.html)，上採樣參數見[interpolate](https://docs.pytorch.org/docs/stable/generated/torch.nn.functional.interpolate.html)。小型U-Net是理解像素模型的基線；本課合成資料的收斂不表示可直接用於醫療診斷或其他真實高風險用途。

## 交叉熵Dice與損失設計

## 先讓loss與任務定義一致

互斥多類別分割通常以`CrossEntropyLoss`接收`[N,C,H,W]`logits與`[N,H,W]`整數target；二元單通道可以採`BCEWithLogitsLoss`與同shape的浮點 $\frac{0}{1\mathrm{target}}$ 。不要先sigmoid又送BCEWithLogits，也不要先softmax再送一般多類別交叉熵。名稱含logits的loss通常已處理相應的數值穩定運算。

若交叉熵遇到`Target 255 is out of bounds`，不一定是類別數要改成256。先確認255是否代表ignore，若是就設定正確ignore_index並讓所有評估也使用相同有效區域。錯誤的mask映射可以讓訓練看似運作，實際監督卻完全不同。

## 像素交叉熵與類別不平衡

每個像素都是一筆監督時，大背景可能主導平均loss。可以比較類別權重、取樣策略或其他損失，但權重必須基於train資料與任務成本，不用test分布決定。過大的前景權重可能增加誤報；所有權重都要配合前景／背景切片和固定疊圖驗證。

像素並不是彼此完全獨立的自然樣本。同一張圖有一萬個像素，不代表你有一萬個獨立個體；資料切分與不確定性分析仍要尊重原始圖、病人、拍攝群組等層級。把像素數當獨立樣本數可能高估證據強度。

## 可微的soft Dice算例

本課示範一種線性分母soft Dice：p是前景機率、y是 $\frac{0}{1}$ 真值，只在有效像素計算。不同研究也可能用平方分母、不同smooth或類別平均，因此實作需註明定義，不能只寫「Dice loss」。

$$
L_{Dice}=1-\frac{2\sum_i p_i y_i+\epsilon}{\sum_i p_i+\sum_i y_i+\epsilon}
$$

四個像素的真值為`[1,1,0,0]`，預測前景機率`[.8,.6,.3,.1]`。交疊和1.4、預測和1.8、真值和2，忽略極小 $\varepsilon $ 時soft  $\mathrm{Dice}=\frac{2.8}{3.8}\approx 0.7368$ ，loss約0.2632。若先以0.5閾值二值化，硬Dice會是1，但這個非平滑步驟不適合直接當一般梯度訓練的輸出。

[V-Net原始論文](https://arxiv.org/abs/1606.04797)是Dice相關訓練目標的歷史閱讀，本文算例與上述線性分母政策獨立寫明，不冒稱逐式複刻其所有設計。

## 組合損失要知道每項在做什麼

可用 $CE+\lambda  \mathrm{DiceLoss}$ 作實驗起點：前者提供逐像素分類訊號，後者關注區域重疊。但兩項梯度尺度、類別平均與batch聚合不同，不能因加總後數字下降就斷言兩者都改善。分別紀錄CE、Dice loss與正式硬指標，並固定 $\lambda $ 、背景是否納入及忽略政策。

對多類分割，先對logits沿channel softmax，再逐類建立y的one-hot；ignore區不能先one-hot成第255類，應先建立valid mask並安全處理索引。若某類在batch沒有真值，是否排除、只懲罰假陽性或納入smooth，會影響梯度與報告，應明定而非依函式預設不經檢查。

## 小心分母與空有效區

 $\varepsilon $ 避免除零，不代表它可以取代語意政策。當真值與預測都空，硬Dice可能定為1或排除平均，但需固定；全ignore batch則沒有可評分資料，不應當成完美分割。若先把所有ignore補成0，會把原本未知區域大量變成背景，悄悄改變loss。

練習：同樣四像素真值，模型輸出`[.51,.51,.49,.49]`，硬Dice仍為1，soft Dice約0.51。這表示類別選擇剛好都對，信心卻接近邊界。不能只用硬Dice判定輸出機率可靠，也不能只用soft Dice替代正式二值結果。

## 實作檢查與來源

驗收包括：完美logits的loss低於反向logits；ignore像素內容改變不影響有效區loss；全ignore有明確處理；梯度為有限值；class ID不被照片正規化。API查[CrossEntropyLoss](https://docs.pytorch.org/docs/stable/generated/torch.nn.CrossEntropyLoss.html)與[BCEWithLogitsLoss](https://docs.pytorch.org/docs/stable/generated/torch.nn.BCEWithLogitsLoss.html)。本課數值為原創算例，非模型benchmark。

## IoU與Dice的分母

## 每個指標都先寫出有效集合

對某一類c，令G為真實屬c的有效像素集合，P為預測屬c的有效像素集合。ignore區域先從兩邊都排除；在未知區域亂猜不應偷偷變成背景TP。TP是交集，FP是P中不在G的像素，FN是G中不在P的像素。這些量都是像素計數，不是物件數。

$$
IoU=\frac{TP}{TP+FP+FN},\qquad
Dice=\frac{2TP}{2TP+FP+FN}
$$

假設G有4像素、P有6像素、交集3像素，則 $\mathrm{FP}=3$ 、 $\mathrm{FN}=1$ 、 $\mathrm{IoU}=\frac{3}{7}\approx 0.4286$ 、 $\mathrm{Dice}=\frac{6}{10}=0.6$ 。兩者看同一個重疊，分母不同，所以不能把Dice 0.6和IoU 0.6直接當相同品質。對同一非空集合，可推得Dice=`2IoU/(1+IoU)`。

## 背景與前景分開看

一張圖99%是背景，全部預測背景的pixel accuracy可達99%，但前景IoU為0。若平均包含背景，數值還可能顯得不差。報告應註明是否包含背景、逐類指標與各類真值像素數，必要時另報前景平均與邊界品質。語意分割mIoU和偵測mAP是完全不同的平均，不可只以m開頭就混為一談。

大量物件區域分割良好，也可能把兩個相接物件合在一起，語意IoU仍很高；如果任務要計數，還需實例層級評估。反之，物件數對了但輪廓粗糙，不能代表精確面積測量可用。

## 全資料累積與逐圖平均不同

圖A有一個真值前景像素且預測完全正確，圖B有99個真值前景像素卻全部漏掉，沒有其他前景預測。逐圖IoU平均是 $\frac{1+0}{2}=0.5$ ；先累積交集／聯集再計算，為 $\frac{1}{100}=0.01$ 。前者讓兩張圖等權，後者讓較大集合貢獻較多權重。兩者都可用於某些分析，但不能不標示地交替報告。

若做逐類macro平均，每類等權；若合併像素做micro，常見大類可能主導。先選擇符合問題的主指標，再用其他切片補充。不要在結果出來後，才選看起來最高的聚合方式。

## 空集合政策要可讀而且可測

某張圖沒有類c，模型也沒預測c，此時IoU是 $\frac{0}{0}$ ，數學上未定。可定義為1，表示對空類正確保持空；也可排除該類該圖的平均。但若有很多空圖，全部定1可能把平均抬高，因此應另報有目標圖的表現與空圖誤報。

若G空但P不空， $\mathrm{IoU}=0$ ；若G非空而P空，IoU也為0，但兩者分別是誤報與漏報。全ignore圖則不是普通空背景，應標示無有效資料，不作完美結果。實作若使用 $\varepsilon $ ，要確保沒有悄悄用數值技巧決定這些語意。

## 用confusion matrix保存可重算的計數

對C類資料累積 $C\times C$ 矩陣，列代表真實類、欄代表預測類。某類TP是對角線；其列總和減TP是FN，其欄總和減TP是FP。先排除ignore，檢查預測與真值ID範圍，再累積。保留矩陣和label map，就能重算多種逐類指標，不只留下摘要小數。

練習：三類矩陣的類1列總和10、欄總和12、對角線8，IoU與Dice是多少？ $\mathrm{FN}=2$ 、 $\mathrm{FP}=4$ ， $\mathrm{IoU}=\frac{8}{14}\approx 0.5714$ 、 $\mathrm{Dice}=\frac{16}{22}\approx 0.7273$ 。若你把欄列方向交換但公式仍一致，IoU可能恰好不變；因此還要用非對稱例子驗證precision與recall，確認方向真的正確。

## 交付與來源

提交逐類計數、背景政策、空集合政策、聚合層級、ignore數量及至少一張邊界失敗圖。指標的跨任務注意事項可讀[Metrics Reloaded原始研究](https://www.nature.com/articles/s41592-023-02151-z)。本單元數字均為獨立集合算例，沒有聲稱任何真實資料性能；請使用保存的整數計數重算，避免只以已四捨五入的小數比較模型。

## 分割練習與解析

## 題目一：為什麼永遠預測背景

你的模型輸出`[N,1,H,W]`，推論呼叫`argmax(dim=1)`，所有像素都變0。這是否表示模型完全沒學到？

**解析：**只有一個channel，argmax索引永遠為0，與模型學到什麼無關。二元單logit路線應sigmoid後按固定門檻二值化，訓練搭配同shape浮點 $\frac{0}{1\mathrm{target}}$ 與相容loss；若採兩個互斥類別logits，才沿channel argmax。先修正輸出解碼契約，再評估是否需要重新訓練。

延伸：三類互斥分割的logits為`[4,3,64,64]`，整數target應是`[4,64,64]`。若target多了一個單位channel，可明確確認後移除；不能對所有情況任意squeeze，否則batch  `size=1` 時也可能把batch維度一起刪掉。

## 題目二：神祕的mask新類別

原始mask只包含0、1、255，經過資料增強後出現37、82等值。你應把類別數改成256嗎？

**解析：**先查是否把離散mask當照片做bilinear、顏色擾動或正規化。這些新值多半是插值或錯誤映射造成，增加類別數會掩蓋資料錯誤。回到原始mask，使用清楚的label map與保留離散值的幾何轉換，並測試輸出唯一值仍在允許集合內。255在本課是ignore，不是前景類別。

若RGB顏色mask因JPEG壓縮出現近似色，也不應自動採最近顏色而不記錄。應從無損原稿重匯出，或建立有證據的修復流程，保留未知色數量與人工核對記錄。

## 題目三：手算有效像素

四個位置的真值是`[1,1,0,255]`，預測是`[1,0,1,1]`。255忽略，請算前景IoU與Dice。

**解析：**只看前三格， $\mathrm{TP}=1$ 、 $\mathrm{FN}=1$ 、 $\mathrm{FP}=1$ 。 $\mathrm{IoU}=\frac{1}{3}$ 、 $\mathrm{Dice}=\frac{2}{4}=0.5$ 。最後一格無論預測0還是1，都不改有效區結果。若把255先補成背景，最後一格會多一個FP，分數變成另一個問題的答案。這也是訓練與評估必須共用valid mask政策的原因。

再把四格全部改成255，此時沒有有效資料，應回報明確無可評分狀態，不能因分子分母都加 $\varepsilon $ 就自動記成完美分割。

## 題目四：哪個平均回答你的問題

圖A有1個前景像素且完全正確；圖B有99個前景像素且全漏。逐圖平均IoU是0.5，全資料累積IoU是0.01。哪一個是計算錯誤？

**解析：**兩者聚合權重不同，不一定有算錯。若問題是「隨機選一張圖，平均分割品質如何」，逐圖平均可對應某種圖像等權分析；若關心全部前景像素的整體覆蓋，累積計數是另一個角度。報告需把聚合層級寫清楚，並提供兩圖大小與樣本分布。不可在兩個模型間使用不同平均方式。

## 題目五：接錯的U-Net

decoder是`[2,24,32,32]`，skip是`[2,16,33,33]`，直接沿channel串接為何失敗？

**解析：**空間尺寸不同。先回到pooling、padding與上採樣的設計，決定補邊、裁切或依skip尺寸插值，並以已知幾何圖案檢查對齊。空間一致後串接得到40通道，後續卷積的input channels也要對應40。不能只改通道數就修好空間問題，也不該每次臨時裁掉不同一側。

## 一份可重現的分割交付

至少保存原圖清單、群組切分、label map、ignore與邊界政策、模型權重、前後處理、逐類confusion matrix、聚合規則與固定疊圖。小型合成資料可以驗證loss下降與形狀，但進入真實任務前仍需代表性標註與獨立測試。

自我檢查：能否說明背景ID與ignore ID不同？能否解釋soft Dice與硬Dice不同？能否找出一張高pixel accuracy卻前景全漏的圖？能否讓另一人從保存的計數重算IoU？這些比只跑出一條漂亮loss曲線更能證明你掌握了分割流程。

原始API可回查[CrossEntropyLoss](https://docs.pytorch.org/docs/stable/generated/torch.nn.CrossEntropyLoss.html)與[Mask型別](https://docs.pytorch.org/vision/stable/generated/torchvision.tv_tensors.Mask.html)。題目為原創教學例，不代表正式資料集結果。

## 實例與全景分割

一張圖有兩個相接杯子，語意分割完整覆蓋所有杯子像素， $\mathrm{IoU}=1$ 。是否表示實例分割完美？不表示；若模型只給一個instance，它沒有正確分開兩個物件。再問：把連通元件直接當instance可行嗎？只在任務幾何和物件分離條件支持時才可能，不能通用於接觸物件。

請將同一張原創圖分別畫成語意、實例與全景答案，附上ID對照。正式全景資料格式與程式可查[COCO panoptic API](https://github.com/cocodataset/panopticapi)，查核2026-11-23。

## 提示式基礎模型與SAM

「模型在真值框提示下IoU很高，所以全自動物件辨識很可靠」有什麼缺口？它尚未驗證如何找到物件、如何決定類別、提示取得成本與漏檢影響。請將流程拆成尋找目標、提示產生、mask生成、人工確認四步，分別列輸入、輸出與評估。若任務只需人工點選後快速描邊，則應用互動時間與修正次數衡量價值，而非假裝它是全自動分類器。

## 開放詞彙與零樣本辨識

## 不再只問固定訓練類別

傳統封閉集分類器通常有固定的輸出類別表；若要新增類別，常需修改頭與訓練。圖文共同表示則讓影像與文字進入可比較的向量空間，利用候選描述評分。[CLIP原始論文](https://arxiv.org/abs/2103.00020)是這條路線的經典來源。這不表示模型沒有訓練過，而是可在某些新任務上不進行該任務特定的監督微調。

零樣本仍依賴預訓練資料與提示設計。若預訓練是否看過某張測試圖未知，應誠實記錄；「我們沒有用這份標註微調」和「模型從未接觸任何相關資料」是不同主張。不要把zero-shot翻譯成沒有任何既有知識的憑空辨識。

## 從向量手算一次候選排序

設原創玩具影像向量為`[1,0]`，候選文字向量分別是「圓形」`[.9,.1]`與「方形」`[.2,.8]`。先各自L2正規化，再做內積，可得約0.9939與0.2425，前者較相似。這些數字只是人工向量的幾何示範，不是實際語言模型的embedding，也不能據此推論中文詞彙的真實表現。

$$
s_k=\frac{v^\top t_k}{\lVert v\rVert\lVert t_k\rVert}
$$

若再以溫度或模型尺度做softmax，得到的是此候選清單內的相對分數；把清單改成另外十種物件，分數分母也會改。高相對分數不保證照片真的包含該物件，更不保證是經校準的真實機率。

## 描述文字本身就是實驗設定

「狗」、「一張狗的照片」、「玩具狗」與「狗的素描」可能對應不同概念。多語言、否定語句、細粒度材質、數量與相對位置也可能有不同效果。先建立固定候選描述和驗證流程，再比較prompt ensemble或領域描述；不應針對test逐張改到答案正確。

如果你的用途是找工廠零件，至少測近似外形、缺陷、反光、遮擋與真正不在清單中的物件。候選類別只含「合格」與「不合格」時，模型仍可能被迫二選一；需要未知拒絕政策時，可以考慮相似度、候選margin或獨立開放集方法，但門檻都要在代表性驗證資料估計，不能憑一個固定數字承諾可靠拒答。

## 整張圖相似度不等於物件定位

全圖embedding可以說明哪個文字與整張圖較相似，卻不直接給出每個物件的框或mask。一張圖同時有三樣物品，最高分可能只反映最顯眼者。開放詞彙偵測器將語言條件和位置預測結合，例如[Grounding DINO原始研究](https://arxiv.org/abs/2303.05499)；它仍需要用框的評估規則檢查定位、重複與漏檢。

若把文字偵測接到提示式分割，整條管線要保存文字、偵測框、分數與mask版本。前段類別描述錯誤時，後段可能精準分割了錯誤物件。漂亮的遮罩不能反過來證明語意判定正確。

## 模型選用與授權

固定官方模型卡、權重版本、tokenizer與影像前處理；跨模型使用另一套resize、crop或normalize可能改變表示。下載與大型模型推論是選讀條件，本課離線向量例子只驗證相似度算法，不冒稱已執行CLIP或Grounding DINO。模型與資料授權、隱私和用途限制要分開查核。

練習：候選清單只有「蘋果」與「香蕉」，輸入照片其實是扳手，softmax仍給蘋果0.8。你能宣稱照片80%可能是蘋果嗎？不能；模型被要求在兩者中相對選擇，缺少未知機制與相應校準。請新增未知測試集、固定拒絕規則並報覆蓋率與錯誤率，而不是只加入一個「其他」詞就假定問題解決。

## 關鍵點姿態與標註可見性

## 點的語意比座標更早決定

關鍵點任務不只是找亮點，而是找具有固定語意的位置，例如左肩、右肩、左肘與右肘。資料必須有一致點順序、人體左右規則與連線表。同一張照片的畫面左側未必是人物左手，尤其人物面向鏡頭時，若未固定解剖左右，標註就會互相矛盾。

單人姿態可直接預測一組點；多人姿態還要判斷哪些點屬於同一個人。top-down先偵測人再估點，bottom-up先找點再分組，各有不同錯誤路徑。人體框漏掉、左右配錯與個別關節偏移，不應全部只寫成平均點誤差。

## 可見、遮擋與未標註不同

COCO的每個關鍵點包含x、y與v： $v=0$ 表示未標註， $v=1$ 表示有標註但不可見， $v=2$ 表示已標註且可見。來源是[COCO正式格式](https://github.com/cocodataset/cocodataset.github.io/blob/master/dataset/format-data.htm)。這些值不能隨意當成三種類別機率；模型的loss與匯入器要依自己的介面解讀，保留原始標註供評估。

未標註點常以零座標伴隨 $v=0$ 表示，但不能把左上角真實座標(0,0)都當缺失。是否有答案由標註欄位決定，不由座標是否剛好為0猜測。遮擋點的標註品質也要檢查：可見影像證據有限，人工推測的誤差可能較大。

## 幾何轉換還包括交換語意

水平翻轉影像時，不只x座標改變；左肩與右肩、左膝與右膝的索引也要依對照表交換。若只翻x不交換語意，模型會在一半增強資料學到反向的人體左右。這種資料可能仍能畫出看似合理的骨架，卻在需要左右判斷的用途出錯。

以 $W=100$ 的玩具資料、點中心座標採0到99為例：左肩在(20,30)、右肩在(70,30)，鏡射位置分別是(79,30)、(29,30)，再依語意交換欄位。注意這裡是像素中心索引的`W−1−x`示例，與前面連續框邊界的`W−x`約定不同；若採另一連續點座標系，需依該轉換器契約處理，不能混用。

## 距離需要合適的尺度

預測點(13,14)、真值(10,10)，像素距離是5。對很小的人和充滿畫面的人，5像素的相對誤差不同，因此評估常依人物尺度或指定身體距離正規化。PCK要說明正規化分母與正確門檻；COCO keypoints使用OKS，並依關鍵點、尺度與可評分狀態處理。具體規則見[COCO keypoints評估](https://github.com/cocodataset/cocodataset.github.io/blob/master/dataset/keypoints-eval.htm)。

不要把關鍵點AP和bbox AP混為相同定位品質；兩者相似度定義不同。也不要把2D點直接當3D關節角度：投影、相機位置、遮擋與透視都會改變畫面角度，若需要實際運動量測，需要額外標定與用途驗證。

## 姿態資料的獨立切分

同一人、同一錄影或同一場景的連續幀高度相似。若隨機按幀切分，測試可能只驗證同一動作的近重複畫面；應依人或影片等目標泛化層級切分。另看不同體型、服裝、輪椅或輔具、遮擋與鏡頭角度，且保護可識別人物資料。

練習：一個模型左右肩都找對位置，但輸出的左右ID顛倒，能否只用無序最近點距離評分？不能，那會掩蓋語意錯誤。應依固定點名比較，並檢查左右對稱點的混淆。再用一張不對稱姿勢測翻轉轉換，才能看出對照表是否正確。

## 實作與交付界線

本課此單元提供關鍵點資料與評估方法，未將大型姿態模型或3D量測列為離線訓練驗證。若選用現成模型，保存其點順序、可見性政策、權重與前處理；不要將一般畫面骨架當成診斷、復健處方或精密人體量測。交付時附點名表、翻轉對照、可見性統計與失敗圖，讓其他人能看懂座標代表誰。

## 追蹤與影片中的資料邊界

## 找到物件，還要知道是否同一個

逐幀偵測可以每張圖都找出兩個人，卻在兩人交錯後把身分交換。追蹤要維護跨時間的track ID，常見流程是預測位置、取得偵測、計算關聯成本、配對既有軌跡，最後建立新軌跡或標記暫失。track ID是此影片流程的識別碼，不等於真實姓名，也不應默默延伸成跨場景個人身分辨識。

先定義需求：只要計數穿越虛擬線、維持短片內ID，還是量測運動路徑？需要的時間穩定性與錯誤成本不同。沒有相機標定時，像素路徑通常也不能直接換成真實公尺與速度。

## 一次簡化關聯算例

兩個既有軌跡A、B的預測框，對當前偵測d1、d2的IoU矩陣為`[[.8,.1],[.2,.7]]`。用`1−IoU`作成本，一對一配對選A→d1、B→d2。下一幀若兩人交叉、框高度重疊，單靠IoU可能不夠，需要運動模型、外觀特徵或其他可靠資訊；這些訊號也可能受遮擋、光線與相似衣著影響。

關聯的幾何閾值通常用來拒絕不合理配對，而不是強迫每條軌跡都找最近偵測。若完全沒有合適候選，暫時保留lost狀態可能比錯配更合理；保持多久則依幀率、遮擋與任務成本設定，必須保存版本。

## 低分偵測不一定全是背景

[ByteTrack原始論文](https://arxiv.org/abs/2110.06864)提供一個重要思路：部分低分偵測仍可能是被遮擋的真物件，可用與既有軌跡的關聯資訊進一步判斷。這不等於所有低分框都直接建立新ID；新軌跡與既有軌跡延續的信心政策可以不同。

用玩具例子說，某人上一幀分數0.9，這一幀被柱子遮擋只剩0.3；若框位置和運動預測相符，可能值得延續軌跡。但空白區突然出現0.3框，沒有相應軌跡，就不應給相同待遇。這些數值為教學情境，不是ByteTrack的通用最佳門檻。

## 時間戳比「第幾幀」更多資訊

30FPS的影片若掉幀，兩個相鄰輸入可能相隔 $\frac{1}{30}$ 秒或0.2秒。運動模型與速度估計要使用正確時間差，不能永遠假設一步等長。批次處理時也要維持每段影片的順序、狀態重設與鏡頭切換政策，避免把上一段影片的軌跡帶到下一段。

若端到端流程含解碼、佇列與模型延遲，畫面上最新框也可能對應較舊時間。需要即時反應的產品應監控資料新鮮度、掉幀與排隊時間，不能只看模型單次forward多快。

例如30FPS來源在佇列累積15幀，即使模型每幀只花10毫秒，使用者看到的物件位置仍可能至少落後半秒。可選擇丟棄過時幀或控制佇列上限，但政策改變後，運動預測也必須使用新的實際時間差。

## 偵測AP不能代表追蹤身分穩定

兩個追蹤器可有相同逐幀框，卻有完全不同ID切換次數。需要同時看偵測、定位與關聯品質，並依正式影片協定使用IDF1、HOTA等指標。[HOTA原始研究](https://arxiv.org/abs/2009.07736)討論了追蹤評估的多個面向。本文的IoU配對算例只驗證關聯概念，不冒稱完整HOTA實作。

建立固定失敗片段：兩人交叉、長時間遮擋、出入畫面、相機移動與相似外觀。逐段看ID是否保持、是否產生碎片與假軌跡，並附片段長度與真實物件數。只挑一段順暢追蹤的展示影片，不足以代表整體可靠性。

## 切分與隱私

先按影片、人物或拍攝場景切分，再產生幀與裁圖。相鄰幀分到train/test會造成近重複洩漏；同一追蹤器狀態也不能跨資料切分延續。保存原始影片或外觀embedding涉及可識別資料，應依用途最小化留存，採適當存取與刪除政策。

練習：逐幀偵測百分之百正確，兩個人交錯後ID交換，能否宣稱追蹤完美？不能。若用途是每人累積停留時間，ID交換會把紀錄接給錯人；必須驗證關聯而非只算框。請畫三幀玩具影片，分別列det_id與track_id，讓身份交換的時點可以被精確指出。

## 進階視覺練習與解析

## 題目一：像素正確，物件數卻錯

某系統把兩個相接蘋果的所有像素都分對，卻只輸出一個物件。報告寫「分割 $\mathrm{IoU}=1$ ，所以計數完全可靠」。哪裡缺少驗證？

**解析：**語意分割只表示像素類別，未必區分instance。要計數，需檢查每個真實物件與預測instance的配對、分裂與合併錯誤；不能只看合併後的前景像素。若使用連通元件當物件，也要驗證接觸、碎片與孔洞情境，避免把資料幾何假設當一般事實。

請交出相同影像的語意mask、instance ID圖與ID對照表。先定義「一個蘋果」的標註政策，對嚴重遮擋或只露出小部分的物件也保持一致，再設計計數驗收。

## 題目二：提示來自真值，還算全自動嗎

甲系統用人工點選一次；乙系統用真值框；丙系統用自動偵測框，各自得到IoU0.8。能否直接說三者一樣好？

**解析：**提示來源、取得成本與錯誤分布不同。真值框是oracle條件，不能當自動流程；人工點選要報互動預算與時間；自動框則要把漏檢和錯框納入端到端結果。三個0.8只在各自條件下描述mask品質，並未建立公平的整體比較。

版本也要固定：經典SAM、SAM 2與具概念提示的SAM 3系列，支援的條件與環境不相同。查核時已存在SAM 3.1，不應把早期限制套在全系列；同時也不能把新版官方硬體測速當成本課電腦實測。

## 題目三：高softmax分數的扳手

候選詞只有「蘋果」與「香蕉」，照片是扳手，模型仍給蘋果0.9。是否代表它以90%信心辨識正確？

**解析：**這是候選清單中的相對分數，可能只是兩者之中較像蘋果。需要開放集拒絕時，要有代表性未知資料、固定門檻、覆蓋率與錯誤率評估；加入「其他」詞不會自動保證可拒絕所有未知。也應檢查prompt、前處理與模型對該領域的適配。

延伸：若整張圖相似度最高為「杯子」，能否立即畫出杯子框？不能，定位需要額外方法或模型輸出。全圖相似、物件框與精細mask是不同層級的答案，管線中每一段都要保留可檢查的中間結果。

## 題目四：翻轉後的左右肩

一個關鍵點增強函式只做x鏡射，不交換左肩與右肩的語意索引。為何骨架看起來正常，仍可能訓練錯？

**解析：**人體左右是點的語意，不只是畫面位置。對稱骨架可能掩蓋左右ID顛倒，應用不對稱姿勢、明確點名與固定flip map驗證。可見性也要保留：未標註、已標註但遮擋與可見不是同一狀態，不能僅用座標是否為零猜測。

2D姿態圖也不等於3D關節角或臨床評估。若用於訓練動作分析，要說明鏡頭、尺度、遮擋與專業判讀需求，而不是以一個畫面角度給出超出資料支持的結論。

## 題目五：框全對，ID全錯

三幀影片中每個人的框都完全正確，但第二幀後兩人的ID交換。偵測AP能否看出問題？

**解析：**逐幀偵測評估不檢查跨幀身分，可能仍給高分。需看ID切換、關聯指標與任務結果，例如每人停留時間。時間戳、掉幀與軌跡狀態重設也要納入檢查；不同影片不能無意延續同一組track狀態。

## 選擇你的下一個小專題

若需要量面積，先做語意mask與幾何標定；若需要數物件，做instance或偵測計數；若需要人工快速描邊，評估提示與修正時間；若需要文字找物件，驗證開放詞彙定位與未知拒絕；若需要影片持續身份，驗證關聯與時間資料。每個專題先寫輸入、輸出、失敗成本、獨立資料與可重算指標，再挑模型。

## 分布改變與域外輸入

**題目：** 某模型在新相機照片的平均信心仍為0.98，但夜間正確率只有60%。能否說「校準良好，而且沒有域外問題」？請提出下一個最有區辨力的檢查。

**解析：** 不能。平均信心沒有與同一群樣本的正確比例對照，也沒有定義域外範圍。先以同一張原始影像比較舊、新推論管線的輸入張量，排除通道、尺寸與正規化錯誤；再固定模型，分日夜與相機切片計算正確率、信心與拒答表現。只有定位變化位置，才能決定是修前處理、補資料，還是改任務邊界。

# 可靠性練習與解析

## 使用方式：先保存答案再看解析

本章練習使用原創計數、logits與情境，不需要下載人臉、醫療影像或預訓練模型。每一題先寫出資料單位、分母、觀察與尚未驗證的推論，再提出下一個能區分原因的檢查。合格答案不只給一個百分比，還應說明這個百分比允許做出哪些決定。

可以建立一份簡短表格：`case_id / observed / hypothesis / next_check / acceptance / fallback`。把觀察和假說分欄，能避免在報告中把「疑似背景捷徑」改寫成「已證明模型靠背景」。完成後，再回到分布改變與域外輸入（見完整課文）至影像隱私授權與生物辨識（見完整課文）檢查自己的條件是否完整。

## 案例：整體分數與夜間失敗

某批次日間80張、正確76張；夜間20張、正確12張。請計算整體與兩個切片的Accuracy，再評估「新相機整體88%，所以所有時段都可直接上線」的說法。

**解析：** 整體88%，日間95%，夜間60%。整體平均沒有替夜間提供相同證據。先核對新舊管線是否對同一影像產生相同輸入張量，再查夜間類別組成、物件尺寸與影像品質。下一輪資料若夜間占比改為50%，在兩切片性能不變的假設下，加權Accuracy為77.5%；這只是組成推算。驗收應列夜間最低表現、樣本數與不確定性，以及不符合條件時重新拍攝或複核的流程。

## 案例：同一份機率算出兩種ECE

第1類機率為`[0.1,0.2,0.8,0.9]`，真值`[0,1,1,1]`。用`[0,0.5)`、`[0.5,1]`兩箱，計算binary class-1 ECE。接著把預測類別信心與是否命中拿來計算top-label ECE。

**解析：** 前者兩箱平均機率為0.15、0.85，對應第1類比例0.5、1，得到0.25。後者的四個信心為0.9、0.8、0.8、0.9，命中率 $\frac{3}{4}$ ，全在上箱，得到$|0.85-0.75|=0.10$。報告要寫清楚事件定義和箱邊界。`19_calibration.py`屬於前一種問題；更換指標名稱不會讓計算自動變成另一種定義。

## 案例：拒答改善與複核容量

100筆請求中，策略A接受70筆、其中7筆錯；策略B接受50筆、其中3筆錯。請計算coverage、selective risk與待處理量。如果每個時段只能複核35筆，能否單憑風險較低選B？

**解析：** A為70%、10%、30筆；B為50%、6%、50筆。B在這批資料的接受樣本風險較低，卻超出35筆複核量。還需計算等待成本、遺漏請求與逾時後動作；可考慮重新拍照、分流、增加複核能力或縮小自動服務範圍。不能把多出來的15筆默認為負類，否則selective risk看似下降，整個服務卻可能增加未完成任務。

## 案例：熱圖像物件，模型是否就可信

某商品分類器的Grad-CAM落在商品中央，但背景替換後大量翻錯。工程師想以「熱圖合理」結案。你需要哪些對照？

**解析：** 先核對背景替換沒有改物件尺度、邊緣與前處理，再固定物件、使用多種背景重測。同時以不同目標類別生成歸因，檢查所用層與參數；在模型副本做參數隨機化，觀察熱圖是否依模型改變。熱圖是調查證據，背景實驗是另一種證據；兩者都不能單獨代表因果證明。改資料後應保留未參與修正的測試集，不只挑一張漂亮熱圖展示。

## 案例：十支影片的一萬張影格

十支影片各取1000張影格，共10000張，模型Accuracy為99%。工程師以10000次獨立二元試驗估計很窄的區間，宣稱跨場域表現已確立。哪裡有問題？

**解析：** 影格具有群內相關，來源場景可能只有十個。先確認測試影片沒有與訓練影片共享來源，再指定目標是影格加權或影片平均。比較兩模型時，可在影片ID層級有放回重抽樣，帶入影片所有影格後計算配對差值；同時列出每支影片的結果與最差情境。即使群組bootstrap正確，也不能代表未蒐集過的新相機、新地點已有相同表現。

## 案例：向量變小是否就能公開

10萬筆512維float32影像向量約204.8MB。若刪除姓名，是否可把它視為匿名教學資料？請列出發布前的檢查與可行替代。

**解析：** 容量只是儲存量，沒有回答向量是否能連回個人、原圖或外部資料。檢查來源用途、再發布權限、ID關聯、存取範圍及備份刪除流程。若目的是教相似度，可以用原創合成幾何圖產生向量，或以人工小向量手算，不必為了示範幾何而加入身分資料。將替代資料的生成方式寫入manifest，仍能保持可重現學習。

## 模型成品與前後處理契約

同一張圖在Python與網頁服務預測不同，先查哪裡？先固定原始檔雜湊，再逐步比較解碼後像素、EXIF方向、resize、通道、range及模型輸入，最後才比logits與後處理。若第一個張量就不同，先修資料流；重訓模型通常無法解決部署前處理錯誤。

驗收時至少保留一張普通、一張邊界尺寸、一張透明影像與一個無效檔案案例；回應應符合已定義的輸入契約。

## 使用現行ONNX路徑匯出模型

只比較argmax相同是否足夠？不夠。logits可能已有很大偏移，只是未跨過排名邊界；在門檻附近就可能改變決策。應同時比有限性、shape、絕對／相對誤差及代表性輸入，再比完整任務結果。套件鎖版和runtime提供者也要一起記錄。

## 數值一致性與部署驗收

某次匯出Top1一致率100%，但少數類recall下降，可能嗎？若這兩個數字真的對同一批輸入及相同label定義計算，就互相矛盾；應檢查取樣、label map、門檻或版本是否不同。先解決報告契約，再推論模型原因。

另問：外接框只差1像素是否可忽略？對200像素物件可能影響小，對2像素物件很大。驗收應連結任務尺度，而不是只用全體平均座標誤差。

## 延遲吞吐記憶體與量化

batch8每批40ms，吞吐約200張／秒；但若只在湊滿8張才處理，低流量下單筆可能等很久。應配合最大等待時間與排隊策略。若服務要求p95低於50ms，只有平均20ms仍不足以驗收。

把尺寸長寬減半，輸入像素四分之一，但端到端不一定快四倍，因為解碼、排隊及固定成本仍存在。必須同時檢查辨識品質，尤其細小瑕疵是否被縮掉。

## 上線監測與資料迴流

某週預測瑕疵率從1%升到5%，是否證明工廠品質惡化？不一定。可能是真瑕疵增加、相機髒污、門檻改動、新產品或程式錯版。先對齊版本與輸入，再做帶標註的切片比較，最後才討論原因。

監測儀表板可以幫忙發現變化，但單一平均數不足以說明因果。把可驗證的訊號與仍待查證的解釋分列，才有可行的改善步驟。

## 部署驗收練習與解析

# 部署驗收練習與解析

本章把前處理、匯出、速度與監測放在同一份交付中，目標是另一個人可以重現並判斷限制。

## 題目：模型檔相同卻結果不同

兩個服務載入完全相同ONNX，A採RGB，B採BGR；A把letterbox補邊去掉再反算框，B直接除單一scale。哪個需要重訓？

解析：先不用重訓。兩個服務計算的是不同輸入及後處理函數，應回到訓練契約統一。對偵測框，先減dx／dy再除實際sx／sy，並保存原圖尺寸；整數取整可能讓sx與sy略不同。

## 題目：動態batch的證據

匯出時指定dynamic_shapes，只用batch2驗證，可以宣稱batch1到8都正確嗎？解析：不能。至少挑範圍邊界與中間值，還要測非法輸入是否符合服務規則。動態宣告是圖的契約，執行測試是額外證據；兩者不能互相替代。

## 題目：計算整體加速

原流程解碼15ms、模型10ms、後處理5ms，模型加速到2ms。總時間由30變22ms，加速約1.364倍。若只報模型5倍加速，不能拿它回答整體服務有沒有達標。

## 題目：沒有真實標註的監測

上線後confidence平均提高，是否表示品質提升？解析：不代表。模型可能遇到更容易資料，也可能變得過度自信。必須配合獨立抽樣標註、類別與設備切片、錯例與版本，才能估計品質。

## 實作任務

執行21_export_onnx.py，確認ONNX checker與三種batch的logit比對都完成；讀取輸出的contract，指出它固定哪些軸、哪些軸動態。再跑22_benchmark.py，在記錄中填入實際CPU、Python、套件、執行緒、輸入大小、warmup及樣本數。

不要把本機速度貼成其他硬體的保證。若只能用CPU，明確記錄CPU；沒有跑CUDA、INT8或手機，就列為未驗證路線。這種界線能讓下一位接手者知道該補哪一個測試，而不是猜測。

## 專題：從影像到分類報告

模型在原生成資料滿分、反轉亮度後大幅降低，是程式失敗嗎？不一定。這是刻意域改變造成的可觀察失效，說明模型依賴的特徵未涵蓋新條件。若要支援反轉，需要合理的訓練資料或策略，並保留新的獨立驗證，而不是修改報告分母。

驗收要求可以從乾淨環境執行、loss下降、保留資料指標與固定錯例可追溯。分數只是其中一項，資料邊界與完整交付同樣需要成立。

## 專題：單物件定位到多物件偵測

把一張完全空白圖輸入單物件定位器，它仍會吐一個框，為何？因為架構沒有「沒有物件」的輸出與訓練資料。低IoU無法完整表示這個失敗，下一步需要物件存在性、背景負例或一般偵測器。先修改任務契約，再選適合架構。

完整偵測專題的驗收除了分數，還要看空目標、重複框、小物件、遮擋、來源切分與原圖座標還原。所有預處理和門檻都保存，才有可重現結果。

## 專題：可訓練的像素分割

真值只有100個前景，預測全背景，pixel accuracy可能仍很高，但前景IoU為0。這揭露了背景不平衡；應看每類IoU、支持像素與物件尺度切片。若真值和預測都完全沒有前景，本課將該類IoU列未定義，不能未說明就視為100%。

對小物件，邊界錯1像素可能影響很大。若任務重視邊界，可另加適當邊界指標與標註一致性評估，但不把不同像素解析度的距離直接混在一起。

交付包括模型、mask類別表、ignore政策、插值與還原方法、聚合方式、錯例圖及來源版本。這些設定與權重一樣影響最終結果。

## 專題：相似影像與異常稽核

前五鄰居全部同類，但來自同一原圖的五種縮圖，能說找到不同相關實例嗎？不能；應去重或依group計分。若業務恰好要找重複圖，則應改用去重任務的真值與評估，不沿用語意檢索分數。

沒有異常標籤，可以保證未知異常recall嗎？不可以。你可以量正常資料的誤報、檢查人工案例，並規劃新異常的蒐集，但未知分布的召回率沒有足夠分母。

## 專題：真實資料導入與品質稽核

資料夾有10000檔，100檔解碼失敗，應報樣本數多少？稽核報總檔10000、有效9900、失敗100及原因；訓練評估以實際使用清單作分母，並檢查失敗是否集中某類。若某類所有檔都失敗，單看整體1%失敗率會掩蓋重大偏差。

## 題目：哪個專題適合需求

「每張圖是否有瑕疵」可先分類；「瑕疵在哪一塊」需要框或像素定位；「邊界精準到像素」偏向分割；「同一物件跨影格的身份」還需要追蹤。任務之間有交集，但不能只換模型名稱而保留不適合的標註和指標。

模型在test100%，上線新相機卻失效，可以把舊test保留做最終證據嗎？

解析：舊test仍可描述舊條件，但不能代表新相機。先查前處理、照明、取樣與來源切片，再建立新部署條件的資料和獨立評估。修正過程中用來選方案的資料成為開發資料，需要另外保留真正未參與決策的集合。

## 延伸實驗

可自行加入第三類、空目標、不同尺度、重疊物件或新背景；先修改資料契約及真值，再實作模型。一次只增加一種複雜性，保留前一版基準。需要外部模型時保存權重條款與雜湊，不讓隱含下載影響離線主線。

完成這些步驟後，你應能說明「為什麼這個任務要這種輸出」「這個分數的分母是什麼」「現在有哪些條件仍未驗證」，而不只是知道如何呼叫模型。

## 視覺任務必要的數學回顧

**題目：** 3 個輸入通道、8 個輸出通道、 $3\times 3$  kernel、 `groups=1`  且有 bias，參數量多少？若每個 logit 都加 100，預測機率會變嗎？

**解析：** 權重  $8\times 3\times 3\times 3=216$ ，bias 8，共 224。所有 logits 同加 100，分子分母的共同倍率會相消，機率不變；穩定實作用減最大值避免數值溢位。這些檢查可用來定位架構與前處理錯誤，不是對模型效果的保證。

## 形狀座標與指標速查

**題目：** 同一預測  $\mathrm{IoU}=0.6$ ，在 IoU 門檻 0.5 和 0.75 下都是真陽性嗎？報告「mAP 90%」缺少什麼？

**解析：** 它只通過 0.5；仍需檢查類別、影像及是否已被更高分預測匹配。mAP 至少缺資料切分、類別範圍、IoU 協定、匹配及忽略政策、評估器版本，單一百分比無法可靠比較。

## 環境與模型故障排查

**題目：** 新模型預測全部相同，有人建議立即把訓練跑十倍長。你最先做哪三個檢查？

**解析：** 先取已知樣本核對前處理數值與標籤；再核對 loss／target 的形狀、類別與 ignore；最後用少量固定資料檢查梯度與能否擬合。若輸入被重複除 255、label 全錯或權重未更新，多訓練通常只延長錯誤。每一步保留能重現的輸入與輸出。

## 中英術語與任務對照

**題目：**「信心高、IoU 低、AP 未知」是否矛盾？`dilation` 和 `dilate` 是否總是同一件事？

**解析：** 不矛盾：模型可以對定位錯誤非常有信心，AP 還需整組預測與真值依協定計算。卷積 dilation 控制 kernel 取樣間隔，形態學 dilate 則擴張前景集合，名稱相近但運算不同。遇到陌生詞先確認它所在的任務與資料角色。
