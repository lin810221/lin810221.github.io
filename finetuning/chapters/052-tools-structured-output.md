# 工具呼叫、結構輸出與Agent適應

訓練可學呼叫格式，工具執行仍需明確契約。

## 工具資料應包含完整情境

若希望模型選工具，資料需包含工具定義、可用參數、使用者問題、呼叫與結果，以及不該呼叫的反例。只訓練函式名稱會忽略參數、權限與工具結果如何被使用。不同模型的tool chat template需依官方格式處理。

結構輸出應分開檢查可解析性、schema正確性與內容正確性。JSON有效但單位錯誤，仍可能讓後續系統失敗。微調可改善遵守規則的傾向，必要時仍搭配受限制解碼、驗證器與可恢復的錯誤處理。

## Agent能力是系統行為

模型產生工具呼叫與實際執行工具之間，應有明確驗證、權限與狀態管理。對外部資料及工具結果的指令也要測試：模型不應因讀到內容就任意改變任務或洩漏資訊。

使用離線工具模擬器建立可重播軌跡，分別測選工具、填參數、使用結果與停止。跨課閱讀可接上MCP及LangGraph的執行工程；本課聚焦如何準備行為資料與驗證模型改變，不把一次工具呼叫當作完整Agent成功。
