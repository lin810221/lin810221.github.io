## 這份教學怎麼讀？

這份教材以 **Python** 為主，從不使用模型的工作流程開始，再逐步接上模型與工具。你不需要先學完 LangChain。建議依序完成前八章，之後再依需求閱讀記憶、人工審核或 RAG。網頁中的程式碼有「複製」按鈕；附有檔名的章節也可以下載完整腳本。

學習目標不是背出 `add_node`，而是能回答四個問題：資料在哪裡？這一步改了什麼？為什麼走這條路？失敗或暫停後從哪裡繼續？

> 核心範例以 LangGraph 1.1.9 驗證。官方文件持續演進；文中標記「1.2+」的功能屬於額外閱讀，不會混入核心範例。這份教材聚焦完整的主要能力與工程實務；所有選用整合的細部參數仍以官方 API reference 為準。

## 從一般函式開始想

假設你要做知識助理，最初可能只需要：

```python
def answer(question):
    docs = retrieve(question)
    return generate(question, docs)
```

但很快會出現新需求：找不到資料要拒答；涉及重要決策要等人審核；工具失敗可重試；使用者明天回來要接著聊；回覆過程要顯示進度。這些需求關心的都是**執行過程的控制與狀態管理**。

LangGraph 提供圖式的編排方式與執行引擎，讓你明確定義每個步驟、資料合併、分支及恢復位置。節點可以只是 Python 函式，也可以呼叫任意供應商的模型。

## 三個核心構件

| 名稱 | 代表什麼 | 知識助理中的例子 |
| --- | --- | --- |
| State | 流程目前知道的資料 | 問題、文件、草稿、審核結果 |
| Node | 讀取狀態並執行工作的步驟 | 檢索文件、產生草稿 |
| Edge | 下一步工作的連接關係 | 有資料就寫草稿，沒資料就拒答 |

可以把圖想成有交通規則的工作桌：State 是桌上的資料，Node 是處理資料的人，Edge 決定交給誰。**Node 不等於 Agent**；一個 Agent 常常包含模型、工具、路由等多個節點。

`START` 與 `END` 是入口及結束的特殊標記，不是需要自己實作的函式。圖也不必是無環圖：允許返回先前節點，因此能表達「提出草稿 → 檢查 → 修改 → 再檢查」。

## Workflow 與 Agent 有何差別？

Workflow 的路徑由程式事先規劃，例如檢索後固定產生答案。Agent 的部分決策交給模型，例如決定呼叫哪個工具。但模型可以做的動作仍由程式提供的工具、路由與權限限制。

| 選擇 | 適合情境 | 要自己處理的重點 |
| --- | --- | --- |
| 一般 Python 函式 | 簡單、短暫、一次完成 | 基本錯誤處理 |
| LangChain `create_agent` | 典型的模型與工具迴圈 | 模型、工具與 middleware 設定 |
| LangGraph | 自訂分支、持續狀態、暫停與恢復 | State 契約與流程設計 |
| LangSmith | 追蹤、評估與相關部署服務 | 資料上傳及服務設定 |

LangGraph 不會自動改善模型的知識、替你提供正確資料，或保證商業流程沒有錯誤。它讓你有地方放檢查與決策，正確性仍需要設計和驗證。
