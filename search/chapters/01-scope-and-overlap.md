# 這門課的位置：把搜尋做成可靠的系統

從商品目錄與知識庫開始，區分表示學習、檢索工程與答案生成。

## 搜尋的輸入與承諾

使用者輸入「AX-100 USB hub」，系統應回傳屬於其租戶、仍有效、可以追溯到來源的商品。搜尋不只是一個相似度函式：還必須決定什麼資料可被查、更新多久可見、找不到時如何呈現，以及故障後如何重建。這些就是本課的主線。

## 與既有課程如何銜接

| 課程 | 主要問題 | 本課使用它的方式 |
|---|---|---|
| [Embedding](../embedding/index.html) | 文字如何成為有意義的向量、模型如何訓練與評估 | 沿用表示與距離的基礎，重點放到儲存與索引 |
| [RAG](../rag/index.html) | 找到的證據如何支援模型回答與引用 | 搜尋服務交付候選，不在這裡重新實作答案生成 |
| 本課 | 索引如何建立、查詢、更新、隔離與維護 | 做出全文、向量、混合搜尋及驗收報告 |

BM25、HNSW 與 Recall 會必要回顧，但從「公式是什麼」往下走到參數、資料結構、失敗案例與實測。你可以直接從本課開始；沒有模型 API 金鑰也能完成主線。

## 兩條實作路線

本機路線使用 SQLite FTS5、Faiss CPU 與 Qdrant Local。它們真的建立與查詢索引，不是把預製排名當作引擎輸出。服務路線介紹 Elasticsearch 和 PostgreSQL／pgvector；預設驗證真實 SDK 序列化與 SQL 契約，只有明確使用 `--live` 才查詢你自行啟動的服務。

向量使用可閱讀的八維手刻特徵，名稱固定為 `fixture-8d-v1`。它方便觀察距離與租戶過濾，不能代表中文語意模型的品質。瀏覽器的七個實驗也會標明模擬邊界；瀏覽器中的候選預算實驗沒有執行 HNSW。

## 最後要交付什麼

專題以來源資料庫為權威，FTS 與向量索引提供候選；服務重新讀來源檢查租戶、版本與有效狀態，再融合排名。你將練習新增、修改、刪除、當機後重送、從備份重建，最後輸出可檢查的 acceptance.json。這份交付同時回答「能不能找到」和「找回來的資料現在能不能顯示」。
