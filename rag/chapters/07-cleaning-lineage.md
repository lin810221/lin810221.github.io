## 清理的目的

清理是讓表示一致、降低版面雜訊，同時保留數字、否定、條件與來源。把一切標點和空白刪掉，看似乾淨，卻可能破壞型號、表格、程式碼和段落。先辨認資料種類，再決定規則。

教材用 Unicode NFC 合併等價字元，再統一換行。這能讓外觀相同的文字更容易比對；它不會自動把所有全形字元、繁簡用詞或同義詞合併。Unicode 正規化有不同形式，不能在不了解用途時任意替換。[Python unicodedata](https://docs.python.org/3/library/unicodedata.html)

## 建議保留三種內容

`raw` 是來源的原始位元組或可重建快照；`parsed` 是解析器抽出的結構；`normalized` 是準備切塊的文字。三者建立明確連結，才能查出錯誤在哪個轉換階段發生。

```text
raw_sha256 → parser_version → parsed blocks
           → normalizer_version → normalized text
           → chunker_version → chunks
```

教材的 offset 對應 normalized text 的 Python 字元位置，不是 PDF 檔案的 byte offset。若你要原頁高亮，需另外保留文字區塊與原頁座標的映射；不能直接用字元索引去截取 PDF 二進位檔。

## 哪些操作需要小心

| 操作 | 可能的用途 | 需要避免 |
| --- | --- | --- |
| 統一換行 | 跨平台一致 | 合併掉段落邊界 |
| 移除頁首頁尾 | 減少重複樣板 | 刪除每頁唯一的日期或分類 |
| 修復斷字 | 連回 PDF 換行的單字 | 改掉真正型號中的連字號 |
| 去除重複 | 降低重複候選 | 跨權限共用不安全紀錄 |
| 遮罩個資 | 降低不必要暴露 | 讓引用無法回查或破壞計算 |

做去重前先確定授權範圍。兩份文件即使內文相同，也可能有不同租戶、授權與生效時間。可以共享計算結果的前提，與可以共享使用者可見的資料，是不同問題。

## 用差異檢查清理結果

選一份文件，輸出清理前後 diff。特別檢查數字、百分號、負號、小數點、單位、型號、日期、`不得` 和 `除非`。規章裡這些小字比修飾語更能決定答案。

對每個清理規則保存版本與測試案例，例如「VPN-403 不會被切成 VPN403」、「0.05 kg 不會變 005kg」。若規則修改影響到 chunk 邊界，就要重建受影響片段與對應向量，不宜只更新顯示文字。

## 實作觀察

`rag_core.normalize()` 刻意保持簡單：NFC、換行和外圍空白。`tokenize()` 另外做英文小寫與詞元抽取，避免把檢索規則直接改寫到原文內容。來源文字與索引用表示分開，答案引用才能保留原句。

## 練習與答案

**題目：**想把所有 `-` 刪掉，避免 PDF 斷行連字。如何驗證？

**參考答案：**先蒐集因換行產生的斷字與真正含連字號的型號、範圍、負數，建立對照。只在可識別的斷行位置修復，保留原始內容與處理規則版本；若無法可靠區分，先保留符號而不是全面刪除。
