## 先保存一個可重現案例

記下原問題、身分範圍、查詢時間、索引版本、程式版本與 request ID。暫停同時更換多個設定，使用同一案例追蹤資料流。若結果受快取影響，先確認是否真的重新執行檢索。

診斷原則是找最早出錯的階段：來源不存在、解析失真、切塊漏條件、召回失敗、排序錯誤、證據沒選入、生成不忠實。早期錯誤常會讓後段看起來也有問題。

## 症狀與檢查位置

| 症狀 | 優先檢查 | 可能修正 |
| --- | --- | --- |
| 完全找不到最新政策 | 匯入 ready、版本指標 | 完成匯入與切換 |
| 命中主題卻答錯數字 | 解析、表格與單位 | 修資料轉換 |
| 型號查詢不準 | tokenizer、精確 lexical | 保留代碼與詞典 |
| 同義問法找不到 | 改寫、dense | 補語意路徑 |
| 前幾名全是重複內容 | 重疊、parent 與去重 | 加候選與多樣性 |
| 正確候選未進答案 | 重排與 context 預算 | 修選擇策略 |
| 證據正確但答案錯 | prompt、模型、支持檢查 | 回到原句與評估 |
| 權限變更後仍見舊答案 | 快取與來源回取 | 更新可見性並失效 |

## 向量相關問題

維度錯誤先看模型設定是否一致；同維度但排名離譜，檢查是否混用不同 encoder、query/document 前綴或資料索引錯配。ANN 回傳太少時，對比精確搜尋與篩選設定，而不是先認定資料不存在。

數值全是零或包含 NaN 應在匯入驗證攔下。文件向量與原文對錯列尤其難察覺，所以 API adapter 按 index 配對、ID 穩定與已知問題的 smoke test 很重要。[pgvector 官方說明](https://github.com/pgvector/pgvector)

## 回答相關問題

對錯誤主張直接找其引用片段，檢查是否真正支持。如果引用 ID 不存在，是結構或映射錯；ID 存在但不支持，是語意忠實度錯；來源過期是版本問題。不同原因有不同修正，不能全部交給更長的 system prompt。

證據不足時亂猜，可以建立無答案題與更明確的狀態；但只調高相似度門檻也可能增加錯誤拒答。門檻要依資料與模型校準，不將 0.7 當作普遍的可信分界。

## 修完後留下回歸測試

把這次問題做成最小資料與明確預期，例如 reader 不得讀 salary、國內數字不得用到國際問題、已失效版不得進 context。再跑原本題集，確認修正沒有讓其他題型退步。

對模型語意問題，保存經人工確認的案例與評分規準；對程式邊界，寫確定性測試。兩種證據可以並用，不能因單元測試全綠就宣稱模型不會再答錯。

## 練習與參考答案

**題目：**問「國際住宿上限」，卻回答國內 2400，第一個問題是什麼？

**參考答案：**先查看候選是否有國際適用條款、metadata 是否保留地區、context 是否同時提供差異。若已提供正確國際規則而模型仍套國內數字，再處理生成與支持檢查。用證據決定階段，避免預先怪罪某個元件。
