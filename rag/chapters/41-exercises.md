## 練習一：切塊不漏字

建立一段 47 字元的測試文字，size=15、overlap=4。列出每塊 start、end，驗證所有字元至少覆蓋一次、每塊不超過 size、沒有空尾塊。

**解法方向：**步長 11，起點 0、11、22、33，最後範圍 `[33:47]`。比較 `normalized_text[start:end]` 與 chunk.text，不要只檢查片段數。再測空文件、剛好等長與 overlap=size 的拒絕行為。

## 練習二：保留精確代碼

新增錯誤碼 `VPN-404` 的文件，與既有 VPN-403 說明不同。確認精確代碼題不會只因兩者都包含 VPN 就拿錯文件。

**解法方向：**保留完整代碼詞元，檢索時可提高精確命中或獨立走 lexical。建立 403、404、未知代碼與含空白變體題。未知代碼不能把最接近代碼的說明當作確定答案。

## 練習三：量測候選與答案

建立十題，其中四題同義改寫、兩題無答案。先跑 BM25，再加入受控詞典或真正 encoder。記錄檢索 Recall@3、答案是否支持與拒答是否合理。

**解法方向：**同一份 corpus 與 qrels 比較；無答案題另算誤答；人工檢查改寫是否保留範圍。不要只報「回答比較自然」。教材五題資料可以示範計算，但不足以完成這份驗收。

## 練習四：權限改動會立刻生效

把文件從 reader 改為 hr，文字不變。重新匯入後，reader 的檢索、context、答案快取與引用回取都不能再取得內容。

**解法方向：**metadata digest 包含 ACL，cache key 包含權限範圍與版本；先阻擋可見性，再非同步更新外部索引。建立兩租戶同 doc ID、空角色與未知租戶反例。

## 練習五：找出故意放入的錯誤

把 context 預算縮小，讓正確證據無法放入；再把舊版 travel 設為 active，觀察結果。你應能用 trace 分辨是預算不足還是版本衝突。

**解法方向：**保存候選與最終 evidence map。候選正確但 context 空是組裝問題；兩版本都 active 是資料生命週期問題。修正後把反例加入測試，並改回原教材資料以維持基準。

## 練習六：做一個有界的 Agent

問題包含住宿上限與報銷期限，要求系統檢查兩個面向。若缺一個，最多重查一次；仍不足就部分回答並列缺口。

**解法方向：**state 保存 attempts 和 missing_aspects；程式判定停止；新查詢不能改權限。量測每輪新增有效證據與總延遲，與固定一次檢索比較。[LangGraph Graph API](https://docs.langchain.com/oss/python/langgraph/graph-api)

## 專案驗收表

| 面向 | 交付證據 |
| --- | --- |
| 資料 | 文件、版本、授權與來源定位 |
| 檢索 | 固定題集、候選排名與指標 |
| 回答 | 主張、引用與無答案行為 |
| 更新 | 冪等、版本切換與刪除測試 |
| 執行 | 其他工作目錄可跑、預設不連線 |
| 維運 | 版本記錄、延遲與可追查 request ID |

完成後，選一個失敗案例，用「最早出錯階段、支持證據、修正與回歸測試」四點說明。能解釋失敗並驗證修正，比單次展示漂亮答案更接近真正掌握 RAG。
