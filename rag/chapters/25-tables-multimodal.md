## 表格不是一串單字

表格的語意來自列、欄、表頭、單位與註腳。`2400` 本身不能回答是住宿上限、補助金額、每晚還是每月。若把欄名與數值切到不同 chunk，檢索可能找到數字卻遺失適用條件。

先選擇資料表示：保留原表格、按列建立帶欄名敘述，或把數值資料放結構化資料庫。不同問題需要不同表示，不能期待同一種文字展平適用所有計算與問答。

## 一個可追溯的列表示

```json
{
  "table_id": "travel-limits-v3",
  "row_id": "domestic-lodging",
  "columns": {"region": "國內", "item": "住宿", "limit": 2400, "currency": "TWD", "per": "晚"},
  "footnote": "需保留住宿收據",
  "page": 5,
  "text_for_search": "國內出差住宿費上限為每晚新臺幣 2400 元，需保留住宿收據。"
}
```

`text_for_search` 協助檢索，結構化欄位負責精確比較與計算，原頁提供查證。表格衍生文字也要能回到同一列，不應讓模型自行重建來源位置。

## 圖像內容的兩條路線

一條是先 OCR、caption 或抽取圖表內容，再以文字檢索；另一條是使用支援相應模態的 embedding 與生成模型，保留圖像定位。前者容易沿用文字流程，但可能丟失版面；後者需處理模態支援、成本與評估。

Gemini 官方 Embeddings 文件提供多模態表示的相關說明，但具體模型與工具支援的檔案種類要分開確認，不能因 encoder 支援音訊就推論所有 File Search 介面也支援。[Gemini Embeddings](https://ai.google.dev/gemini-api/docs/embeddings)、[Gemini File Search](https://ai.google.dev/gemini-api/docs/file-search)

## 版面與來源座標

PDF 可以保留頁碼與 bounding box；掃描頁則保留頁圖、OCR 版本與文字框。回答引用可以顯示頁面和框選範圍，但開啟原圖也要授權。若高亮位置與文字對不上，使用者無法有效查證。

對圖表問題，建立專門測試：軸的單位、圖例顏色、百分比和絕對值、跨頁表頭、合併儲存格、負值。OCR 置信資訊與人工覆核狀態可作資料品質條件，不能只憑模型回答流暢度判斷抽取是否成功。

## 精確計算仍需工具

問「哪一項金額最高」可以由結構化欄位排序；問「圖上是否呈上升趨勢」可以從驗證過的數值計算。生成模型適合說明，計算步驟與中間數據則應留在可重現的程式中。

## 練習與答案

**題目：**資料把「每晚 2400 元」錯抽成「每月 2400 元」，向量搜尋仍命中，哪一層需要修？

**參考答案：**先修解析或資料轉換，再重建受影響片段與索引，並加入單位驗收。這不是把 top-k 調大能解決的問題；生成器看到錯誤證據後，即使忠實引用也會得出錯誤答案。
