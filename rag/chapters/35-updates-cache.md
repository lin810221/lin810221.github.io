## 快取存的是什麼

可以快取文件解析結果、Embedding、檢索結果、prompt 前綴或最終答案。它們的依賴不同，不能全部用同一個 key。文件向量依賴內容、模型與前處理；答案還依賴問題、可見證據、生成設定與權限。

模型 prompt cache 與應用答案 cache 也不同：前者通常重用運算前綴，不代表保存並回傳固定答案；後者會直接回傳已有結果，若失效條件錯誤就會持續顯示舊規則。

## 最小快取依賴

```text
query + tenant + permission_scope + corpus_version
+ query_transform_version + retriever_config
+ generator_model + prompt_version
```

教材 `cache_key()` 示範問題、租戶、角色、corpus 版本與模型的隔離。正式系統可用授權範圍指紋，而不只角色名稱；同叫 reader 的使用者可能仍有部門或文件層級差異。

## 外部索引更新多了什麼

文件記錄更新不等於向量索引和全文索引都已更新。需要保存片段清單與版本，新增新片段、驗證、切換可見版本，再移除舊片段。失敗重試不應產生重複，使用可重算的 ID 和 upsert 語意。

刪除可能是最終一致。應用層可先把文件標成不可見，並讓 query 和引用回取檢查狀態，再非同步完成底層清理。部分託管服務也有刪除一致性限制，需查明當前契約。[OpenAI Retrieval](https://developers.openai.com/api/docs/guides/retrieval)

## 為什麼錯答案一直重複

檢查是不是舊文件還 active、索引指標沒有切換、查詢 cache 沒含版本、答案 cache 跨權限共用，或瀏覽器正在顯示上一輪結果。重複輸出不必然是模型「堅持己見」，也可能根本沒有重新查詢。

除錯時可以暫時關閉相關快取，保存同一請求在各階段的版本與內容摘要。確認問題來源後再恢復快取，並加入失效測試。別用無限制清空所有生產資料代替定位。

## 練習與參考答案

**題目：**更新了住宿上限，向量查詢找到新版，但使用者仍看到舊金額，下一步看哪裡？

**參考答案：**檢查最終 context 是否選入新版、答案快取是否命中舊 corpus、回傳 request ID 是否對應當次查詢、前端是否沿用歷史回應。按資料流確認，不要立刻重做全部 Embedding。
