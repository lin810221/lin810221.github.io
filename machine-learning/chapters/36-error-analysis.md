# 錯誤分析與子群：找出平均分數掩蓋的問題

將錯誤連回資料、標籤、時間與使用者群，而非只調超參數。

## 先保存可追蹤的預測表

每筆至少有樣本ID、split／時間、真值、分數、決策、模型版本；敏感特徵依權限處理。分類分FP／FN，回歸看signed residual與大誤差。只保留平均loss，事後很難知道哪類錯誤造成變化。

## 切片要有假設

依新／舊使用者、缺失率、來源、時間、金額範圍或其他合理群組，看support與指標。群組太小時分數波動大；大量亂切可能找到偶然的極差／極好子群。先定重要切片、列樣本量並追蹤後續資料，不把一次發現當永久規律。

## 如何判斷原因

FP可能是label漏標、特徵時間錯位或threshold過低；FN可能是少數模式沒學到、前處理不一致或資料分布不同。對照代表性案例及資料來源，再提出可測假設。解釋模型某欄重要，不會直接告訴你資料究竟正不正確。

```text
觀察：新plan群recall下降
證據：該群support、unknown編碼率、分數分布、label延遲
假設：未知類別缺少可用訊號
實驗：在train加入可泛化特徵，用未參與診斷的資料驗證
```

## 錯誤修正的資料邊界

可以用train／validation做診斷與改進；看test個案後調模型，test已參與開發。保留後續新資料或使用巢狀流程評估。人工修標籤也要有明確規則與版本，不只修模型剛好猜錯的幾筆來提高分數。

## 公平性與使用限制

不同群組錯誤負擔可能很不同，整體accuracy不能代表對所有群體合理。公平性定義與成本可能衝突，需要問題背景、代表性資料與適當治理；本課提供切片與驗證方法，不從合成資料宣稱符合任何現實公平標準。

## 練習與解答

A群1000筆recall.9，B群10筆recall.5，能否只報整體？解答：應列每群support與不確定性，優先查資料與業務影響。若B全部是部署後新增類別，先查schema與unknown政策，而不是只替整體模型加樹。將每個修正假設與驗證結果記錄，避免無目的調參。
