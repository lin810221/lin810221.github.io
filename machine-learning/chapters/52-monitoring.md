# 實驗、監控與重訓：讓結果有完整脈絡

記錄選擇歷程，監控資料與任務品質，設計可回復的更新流程。

## 每個run保留什麼

問題與label定義、資料版本、split／group／time、特徵規則、候選與預算、seed、環境、CV結果、threshold來源、最終test及失敗例。只存best_score會隱藏試驗數與偏差。資料與模型hash可識別產物，但hash不能替代可重建的來源與規則。

## 監控輸入與輸出

schema錯誤、missing／unknown率、特徵分位數、score分布、接受率、延遲與錯誤。與訓練／已驗證基線比較，設有意義視窗與樣本下限；不是任何小差異就自動重訓。人口組成、業務活動與資料管線都可能造成變化。

## 有label後才看得到的品質

accuracy、recall、校準等需真值，可能延遲數週。監控需按預測時間與標籤到齊窗計算，避免未成熟負例讓recall／event rate失真。若只有被人工選中樣本得到label，也有選擇偏差，不能當整體真實表現。

## 重訓不是自動修復

先判斷是資料壞、schema改、樣本比例變還是關係改；若資料壞，重訓可能學錯。準備新資料版本，以時間／群組一致的驗證比較challenger，重新校準與選threshold，再保存完整artifact與回復路徑。不直接覆蓋唯一模型。

```text
發現警訊 → 查資料與label時效 → 固定新資料版本
→ 重跑完整選模／決策流程 → 獨立驗收
→ 保存新模型與舊版 → 有條件發布與監控
```

## 讓警訊附帶樣本量與下一步

若視窗只有5筆，其中1筆未知類別就是20%；與10000筆中的2000筆同為20%，證據強度不同。報告比例時一起列分子、分母、視窗時間與基線，避免因小視窗波動頻繁啟動昂貴重訓。資料遲到也可能讓某天視窗尚未完整，先確認蒐集狀態。

警訊應連到可執行處置，例如schema失效先檢查資料管線，unknown上升先查新來源，label成熟後的品質下降才進一步比較模型。每次處理留下原因與結果，使監控成為可追蹤決策，而不只是多一張圖。

## 練習與解答

unknown plan從1%變30%，但predict全成功，是否不用處理？答案：需要查來源與新群體品質。某週正例率下降，可能是label尚未到齊，不立即認定模型變好。把監控數字連回時間、支持數與資料契約，才知道警訊意味什麼。
